# 技能：主体库（subjects）

> 适用：剧本已入库，要把角色/场景/道具做成可复用的主体与状态图。

## 1. 收录标准（宁缺勿滥）

- **角色**：全部主要角色都要；同一角色多形态（美艳/恶鬼）做成**同一主体的多张状态图**，不要建两个主体。
- **场景**：≥2 场复用或承载关键剧情的才收；一次性过场不收。
- **道具**：只收有剧情推动或象征意义的（一部短片通常 0–5 个）。

## 1.5 先交交付物，再动数据（2026-11-13 用户反馈：不知道要处理什么、要给用户什么）

动手写库之前，先把下面这张表完整给用户（**不许只报一串名字**）：

| 项 | 每个主体逐行写清楚 |
|---|---|
| 名称 / 类型 / 别名 | 与剧本逐字一致；同一角色多形态只占一行 |
| 身份锚点句 | 性别年龄 + 脸型五官 + 发型 + 体型 + 服装 + 标志物，一句话，全片逐字复用 |
| 状态列表 | 每个 stateTag + 与基础形态的差异（服装/伤势/年龄/形态） |
| 出现集数 | 按剧本实际出现算；不默认全剧，不编 |
| 图片来源 | 「用户提供（路径/链接）」或「待补图」；**禁止写「网上找一张/库里挑一张」** |

缺图时另给一份**缺图清单**：要哪几张、每张画什么（单人、同一张脸、几个画面、景别、光位、背景、
画幅），由用户出图或用画布生成后导入。**不要自己拿开源库/网络图凑数。**

## 1.6 每个主体逐个走（不许批量臆测）

1. `list_subjects` 查重（同名 / 同图 / 同一建筑）；
2. 有参考图 → `read_asset` 亲眼看 → 写身份锚点句 + 把这幅图反推成提示词 → 给用户确认；
3. 没有参考图 → 只交「身份锚点句 + 生成提示词 + 缺图清单」，等用户给图；
4. 用户确认后 `upsert_subject`（dryRun → 确认 → 写入）；
5. 图到位 → `read_asset` 看 → 反推 `prompt` → `upload_asset` → `set_subject_image`（必须带反推 prompt）；
6. 每个主体写完 `audit_subjects`，把 no_image / cross_subject_image / duplicateImage 原样报给用户。

## 1.7 强制字段模板（2026-11-13）：有图按图反推，没图按剧本补全

建完主体后：**角色必须**调 `set_subject_profile({ subjectId, kind, profile, sourceImage? })`；
服务端会校验角色字段、拼出定妆提示词（正面特写 + 正背全身，画面数量写死）。
**场景/道具不强制套模板**：如果已有可直接使用的概念分镜/概念图，走 `read_asset` 看图 → 反推 prompt → `set_subject_image` 即可；
没有现成图时才生成单张概念图，不默认生成多视角宫格/细节拼版。字段不全会拒绝并列出缺项；不许留空、不许凭想象。
无论走哪条路，身份锚点句仍要写进主体备注（`upsert_subject.note` / `set_subject_profile` 都会落）。

**角色（character）profile**

| 字段 | 写什么 |
|---|---|
| 时代基底 / 国家朝代 | 架空古代 / 民国 / 现代 / 科幻…；具体王朝或地域 |
| 物种 / 族裔 / 类型基底 | 人类 / 妖 / 机械…；东亚…；古风英气女侠 / 现代职场… |
| 显著特征 | 一眼能认出的点（斜飞入鬓的长眉、极高挺直鼻梁…） |
| 脸型 / 发型 / 耳饰 | 轮廓、五官、发色发长、发饰；耳饰可空 |
| 身材 / 头身比 / 年龄 | 身高体型、比例（7.9）、岁数 |
| 性格 | 两三个词 + 一句行为倾向 |
| 变装 / 上身着装 / 下身着装 / 鞋子 | 这套状态叫什么；衣料、颜色、纹样、护具、靴子逐项写 |

**场景（scene）profile**：时代基底 / 地点 / 建筑风格 / 空间结构 / 地面 / 墙面 / 门窗（可空）/
光源 / 前景 / 中景 / 远景 / 氛围 / 色调 / 材质与洁净度 / **调度空间**（入口门槛、站位空地、进出通道）/
**色光锁句**（本场景所有轴图逐字复用的一条光色基线，见 3.14）。

**道具（prop）profile**：名称 / 尺寸 / 材质 / 颜色 / 状态 / 边缘与纹理 / 光泽 / 磨损（可空）/ 背景。

- **有参考图**：先 `read_asset` 看图 → 逐项按画面反推（脸型、发型、服装、材质、光线、构图）
  → 带 `sourceImage` 调 `set_subject_profile`。图与剧本冲突时以图为准，并告诉用户改了哪几项。
- **没有图**：按剧本补齐字段；缺的项列成「缺图清单」让用户补，不要编。
- **出图形态 `renderMode`**（2026-11-13，道具按复杂度定形态 2026-11-18）：角色默认 `sheet`（正面特写 + 正背全身，写死 3 个画面）；
  场景/道具默认 `single`（单张概念图，不生成宫格/细节拼版）；`white-bg` = 白底快速图（纯白底、单品居中）——用户只要快速白底道具图时用这个。
  场景只有在用户明确要「四视角/多视角宫格」时才用 `sheet`；四格同场景一致性模型无法保证，默认不做。
  **道具的形态看道具本身**：简单道具（一把刀、一盏灯、一枚印）单视图就够，不要细节拼版；
  结构复杂、装配关系或多部件工艺必须交代清楚的道具，才显式传 `sheet` 出「整体 + 1 个细节特写」（最多 1 个细节，不要同款第二件）。
  道具永远不套角色的三视图口径。
- 模型语言：Qwen 直接用生成的中文提示词；Moss / Krea2 按 `zeroexo://skills/image-prompts` 翻成英文再投喂。
- 提示词由服务端生成，**Agent 不要再手写三视图/场景/道具模板**；返回的 `prompt` 就是页面「提示词」的内容。

## 1.75 主体图自审闸门（2026-11-19 用户硬性要求）

生成或拿到的每一张主体图，挂图前 Agent 必须自己看图逐张审核，不合格直接重出，不许硬挂、不许让用户帮你把关：

- **场景图**：画面必须空——出现任何人物、动物、推车、果蔬等可移动道具 → 不合格，改提示词重出（最多 3 次）；出现角色剪影/背影也算不合格。
- **角色图**：必须单人、同一张脸、同一服装、同一画风；出现多人/合辑/候选宫格 → 不合格。
- **画风一致性**：必须与本项目 `visualStyle` 一致；写实/摄影感混进卡通项目、或明显像某知名 IP 角色 → 不合格，直接重出。
- 重出后仍不合格，不要挂图，把该主体标为待审核并回报用户「哪张图哪里不合格、已试几次」，等用户决定。
- 合格才 `set_subject_image`（场景带 `emptySceneConfirmed`、角色带 `samePersonConfirmed`），并把审核结论写进项目档案（`append_project_log`）。

## 1.8 全剧风格（项目级单值，主体继承）

- 风格不是每个主体各写一套：`script.meta.visualStyle` 存一套快照（presetId / name / prompt / image），
  所有主体/状态提示词继承；单主体不覆盖。
- 工具：`list_style_presets`（39 套：9 导演 / 6 主流 / 8 动画 / 16 题材，含都市、基础写实、邵氏、经典港片）→ 把候选 id 与名称报给用户选 →
  `get_global_style` 看现状 → `set_global_style({ presetId, baseVersion, dryRun, userConfirmed })`。
- `set_global_style` 会删所有主体提示词里的「风格 / 灯光 / 色彩 / 质感」旧行，末尾追加一行
  「风格：<该套片段>」；空提示词不动，人设 / 版式 / 硬约束不动。**必须先把 presetId 与影响报用户确认再写**。
- 页面入口：本剧信息「全剧风格」、主体状态面板「全剧风格」整行（点开同一个画廊）。

## 1.9 主体粒度硬规则（2026-11-13 用户拍板）

- **场景 = 地点/建筑**：一个地点一个主体（如「云顶大厦」）；宴会厅 / 28 层总裁办公室 / 保安部 /
  走廊 / 电梯 / 停车场都是它的**状态（子区域）**，不是新主体。
  - 合并工具：`consolidate_scenes`（先 dryRun 把分组给用户看 → 确认 → `userConfirmed:true` + storyboard `baseVersion`）；
    合并后子区域变状态，各自保留提示词与图。只有独立地点（另一栋楼/另一条街/另一个城市）才建第二个场景主体。
- **角色 = 一个演员**：一个角色主体只能是一张脸；不同演员绝对不建同一主体（同一演员不同造型 = 状态）。
  - 角色已有图再挂新图必须带 `samePersonConfirmed:true`；看脸不一致就停下，建两个主体，不许混。
- **道具 = 一个道具**：同一道具的新旧/破损是状态，不是新主体。
- 提取完主体后、给用户看清单前：先 `consolidate_scenes` dryRun，把分组给用户确认；
  不要把 37 个房间当 37 个场景主体交出去。

## 2. 身份锚点句（外观锁）

一句话封装：性别年龄 + 面部特征 + 发型 + 体型 + 服装 + 标志物。

- 例：`张秀才，明代书生，二十余岁，身形清瘦，面白无须，束发戴儒巾，青布直裰，腰间系素色布带。`
- **锁定后同场景所有提示词逐字复用**；改写 = 视觉漂移，不许「换个说法更通顺」。
- 朝代/服制必须写死（明代束发戴巾、僧人不冠），否则会漂到隔壁朝代。

## 3. 图片规格

| 类型 | 规格 | 说明 |
|---|---|---|
| 角色定妆 | 16:9，画面固定 3 个：正面大头特写 + 正面全身 + 背面全身 | 一张图锁脸+服；**只允许该角色一人、同一张脸**，禁止第二个人 / 多人合照 / 模特合集；多形态各一张（stateTag=美艳/恶鬼/定妆）；不要写「三视图」，模型会自己加侧视图 |
| 场景 | 单张概念图（16:9 或 21:9 按镜头）；已有分镜概念帧可直接复用 | 不强制轴图、不强制多视角；场景提示词**不得描述角色外貌**；有人物的概念帧不能当空场景主体图 |
| 道具 | 默认单张概念图（单品居中）；复杂道具才「整体 + 1 个细节特写」 | 形态按道具复杂度定，简单道具不要细节拼版；干净背景，无手无人物，提示词**不得描述角色外貌** |

### 3.5 风格必须跟剧本走（2026-11-12 用户强调）

- 定妆提示词里的「色彩 / 质感 / 灯光 / 年代」必须由**本剧时代、题材、场景**推断（古装 / 民国 / 现代 / 科幻 / 动画…），
  **禁止**每次都套同一套「1970s 香港 / 邵氏 / 胶片颗粒」。
- 只有剧本明确是复古年代片时才写胶片颗粒与年代滤镜；现代戏用写实自然光、科幻用冷色工业光、古装用暖黄烛火等。
- 可复用的是「画面布局 / 画面数量 / 一致性」这些硬约束；风格块必须按项目重写。
- 用户看到的旧模板里出现的「1970s 邵氏」只属于某一个项目，不是默认值。

### 3.6 同一演员多状态：只挂状态，不新建主体（2026-11-12 灾难复盘，硬性）

- 一个演员 = **一个主体**；美艳态 / 恶鬼态 / 少年 / 受伤 / 定妆……都是这个主体的**状态**，不是新主体。
- 正确：`set_subject_image({ subjectId: 现有主体id, storageKey, stateTag: "美艳态" })`，前端按 stateTag 归到同一主体。
- 错误：`upsert_subject({ name: "沈少（美艳态）" })` 再建一个主体。服务端会直接报 `VALIDATION`
  （同名/同别名已存在），并告诉你现有 subjectId；不要换名字绕过。
- 建主体前先 `list_subjects` 查重；不确定是不是新角色时，先问用户。

### 3.7 清理重复主体：有工具，不要让用户去前端手动删（2026-11-12）

- 重复主体（同名/同别名、合并产生的副本）用 `merge_subjects({ sourceId, targetId })` 并回本体：
  图片/别名/集数/状态都会并入 target，source 删除；先 `dryRun` 看 `movedImages / movedStates`，再 `userConfirmed:true`。
- 只删坏图：`delete_subject_image({ subjectId, storageKey })`；删整个主体：`delete_subject({ subjectId })`。
- 这三个都是破坏性写，必须 **先 dryRun 给用户确认清单，再 userConfirmed:true**；禁止说「MCP 没有删主体/删图的工具，请你去前端删」。
- 合并前必须确认 source/target 是同一演员；不同演员不能合并（服务端只允许同 kind，但同名不同人仍需人工判断）。

### 3.8 主体写完必须自检（2026-11-12 事故后加，硬性）

- 任何 `upsert_subject` / `set_subject_image` / `merge_subjects` 之后，必须调用 `audit_subjects({ projectId })`。
- `images_not_in_tree > 0` 或 `missing_tree > 0`：说明页面会出现「有图但基础状态没图」，
  用 `repair_subject_trees({ baseVersion, dryRun:true })` 看数量，再 `userConfirmed:true` 修复。
- `audit_subjects` 返回的 `no_image` 是**没出图的配角/场景**，不是数据损坏；不要为了清零去删有剧情的角色。
- 集数关联：页面「出现集数」读的是主体树 `states[0].appearEpisodes`，不是 `entity.episodeIds`。
  写完集数后必须 `sync_subject_episodes({ baseVersion, dryRun:true })` → `userConfirmed:true`，
  以剧本实际出现重算；否则页面会全部显示「全部」。
- 禁止把「页面没图」解释成浏览器缓存或让用户重新导入；先跑 audit 拿证据。

### 3.9 剧本「本剧信息」是交付必检项（2026-11-12 用户反馈）

- 每次 `import_script` 或重建剧本后，必须调用 `set_script_meta` 写 **logline（整部剧一句话概述）+ tags（推荐标签）**。
- `get_script` 返回 `metaAudit`；`complete=false` 视为未完成，不允许交付。
- `import_script` 若返回 `scriptMetaWarning`，必须立刻补写，不能忽略、不能等用户提醒。

### 3.10 主体类型新增「备选」（candidate）

- kind 可为 `candidate`（备选）：演员/场景/道具还没定、但不想删的资产放这里，不算正式角色。
- 备选主体同样可挂状态图；定下来后用 `upsert_subject` 改 kind 为正式类型。

### 3.11 同一张图不能挂成多个主体（2026-11-12 用户反馈）

- 新建主体前先 `list_subjects`：如果某个主体的封面/状态图已经是这张图，**复用该主体**（改别名/加状态），不要再新建。
- `audit_subjects` 的 `duplicateImage > 0` 就是重复主体；用 `merge_subjects` 并回本体，保留一个。
- 场景尤其容易踩：同一张场景图被分配给 9 个不同地点，结果看起来全是重复资产。
- **场景主体按物理建筑/园区建一个**（云顶集团、云顶大厦、秦家老宅、天罚总部…）；
  房间/分区（会议室、总裁办公室、地下车库、天台）一律作为该主体的 **状态**，不要每个房间建主体。
- 同一建筑的不同叫法（「云顶集团·会议室」「京海·云顶集团·会议室」）合并到同一主体，写成别名。
  判据：去掉城市前缀后，`·` 前的建筑名相同就是同一个主体。

### 3.12 先看图、再反推提示词、再挂图（2026-11-13 事故后加，硬性）

事故：Agent 只拿到 storageKey 就直接挂图，把六人模特合集挂成「唐启明」的封面——图里根本不是一个人。

- **挂主体图之前必须先 `read_asset` 真正打开这张图**（返回 MCP image 内容块，多模态模型能看到）。
  `set_subject_image` 只认本次会话里读过的图，没读过直接 `IMAGE_REVIEW_REQUIRED`；看不到图就停下问用户，不许猜。
- **角色挂图前必须已经有人设/定妆提示词**（先 `set_subject_profile`）；基础提示词为空直接
  `SUBJECT_PROFILE_REQUIRED`——没写人设就挂图 = 瞎配图。场景/道具例外：已有概念分镜/概念图时，
  `read_asset` 后把画面反推成 prompt 直接挂入，不强制再套模板生成新图。
- **看完必须把画面反推成 `prompt` 再挂**（工具会拒空 prompt）：几个人、是否同一张脸、年龄性别、
  脸型五官、发型、体型、服装材质、姿态、景别、光位、背景、色调、质感。反推的是「这张图里实际有什么」，
  不是「我希望它是什么」。
- **角色图只允许该角色本人**：单人、同一张脸、同一套服装。出现第二个人、多人合照、模特合集、
  候选人群像、别的角色图 = 挂错，删掉重来。
- **场景图必须是空场景，道具图必须是单品无人物**；有人物、动物、苹果/杯子/手机等可移动道具就说明拿错了。
- 场景挂图必须带 `emptySceneConfirmed:true`：先 `read_asset` 看图确认干净；有苹果这类道具直接换图，不许硬挂。
- 同一主体的多张状态图必须能看出是**同一张脸**；对不上就停下问用户，禁止「差不多就挂」。
- 用户给的是多人图/剧照/海报时：先说明「这张图里有 N 个人，要裁出哪一个」，**不要整张挂上去**。

### 3.13 图片提示词八段式（2026-11-13，借鉴 drama-skills）

每张主体图按这个顺序写，别堆形容词：

1. **用途与身份锚点**：这是身份板 / 造型状态 / 地点板 / 道具板 / 风格帧；第一句直接说对象与用途；
2. **当前单一变体**：一张图只写一个状态，不把互斥状态塞进同一张（活人 + 鬼、白天 + 夜）；
3. **构图 / 视角 / 版面关系**：几个画面、每个是什么、谁是主体；
4. **光色 / 材质**：光源、方向、色温、材质与做旧；
5. **背景边界**：纯色 / 中性灰 / 场景空间，写清允许与禁止；
6. **文字与禁止项**：要不要字、字写什么、禁止什么（水印 / logo / 多余人）。

- **身份 vs 变体**：身份板锁脸 / 体型 / 发型 / 标志物；变体只改服装 / 伤势 / 年龄 / 形态，脸不变。
- **年代锚点**：朝代 / 年代 / 地域 / 建筑 / 服制写死，否则会漂到隔壁年代。
- **地点**：同一地点的多视角共用同一组材质与光源；道具写清尺度与状态（新旧 / 破损）。
- **连续性锁**：每个主体留一句「可以原样粘进任何镜头提示词」的外观锁（身份锚点句），后续镜头逐字复用，不改写。

### 3.14 场景概念图规范与出图流水线（2026-11-14 事故复盘，硬性）

**流水线阶段（不许跳步；画布散图未经用户删选不许入主体库）**

1. **调研设定**：按剧本时代/题材/IP 先调研官方或公开可考的建筑形制、地域谱系、服制器物，列成场景设定清单报用户确认；不许拿通用客栈/厅堂模板臆造。本地旧素材不达标的，以外部调研与用户拍板为准。
2. **确认基线**：设定、色光基线、机位清单经用户确认后，才在画布生成场景概念图（默认单张；16:9 或 21:9 按镜头需要）。
   已有可直接使用的分镜概念帧→直接走审核与挂图，不重复生成。
3. **画布审核（Agent 发起，用户可取消）**：图先进画布后，Agent 先列本批审核清单（哪几张、对应哪个主体/机位/状态）。用户可整体取消审核、直接指示继续；否则逐张决定**去留、打分（1–5）、写改进建议**。保留的图：把打分与建议写进图片 `note` 留痕，再走 `read_asset` → 反推 prompt → `set_subject_image` 入主体库；否决的图不挂主体，改进建议回灌下一轮重出提示词。画布未被确认的散图不许挂进主体。
4. **入库自检**：入主体后跑 `audit_subjects`，再 `sync_subject_episodes` 补集数；道具/场景若剧本正文没出现名字，手动补关联，不许默认全部集。

**场景概念图硬约束**

- **默认单张、单机位**：16:9 或 21:9 按镜头需要；2×2 四视角宫格只有用户明确要求才做——一张生成图无法保证四个视角属于同一屋檐下。已有分镜概念帧可直接作为场景参考，不必重新生成轴图。
- **可调度空间**：每张场景图写清入口/门槛、人物站位空地、进出通道；前景柱/框只作边缘框景，不能压住动线；平视大全景，机位高度贴近人眼；前中后三层分别点名。
- **色光锁**：一个场景主体固定一条逐字复用的色光基线句（暗部色 / 光源色 / 地面色 / 木色 / 唯一暖源），该场景所有概念图与后续视频提示词逐字复用；不许每张图各写各的光色导致蓝绿漂移。
- **形制写死**：朝代/地域/建筑构件（梁柱、柱础、梁架、门窗、地面材质）写进 profile，禁止漂到隔壁朝代、隔壁地域；IP 改编以官方设定为准。
- **空场景**：无人、无动物、无可移动小物；场景与剧情意境不符时，先文生图重出或图生图编辑，不许把不像的图硬挂。
- **不得描述角色外貌**：场景提示词只写空间、建筑、材质、光位、动线，不写脸/发型/身材/服装；角色外貌属于角色主体，不属于场景。

## 4. 落地步骤

1. `upsert_subject({ name, kind, aliases, note:身份锚点句 })` —— 先 dryRun，清单给用户确认后才写。
   **新建时不传 episodeIds 会自动按名字/别名在剧本里关联出现过的集**；返回 autoEpisodes 给用户核对，
   若提示「剧本里没找到这个名字」，必须在页面上手动选出现集数，不能默认全部集（2026-11-12 用户反馈）。
2. `set_subject_profile({ subjectId, kind, profile, sourceImage? })` —— **角色必须**按 1.7 的字段表提交；
   服务端校验后生成角色定妆提示词（正面特写 + 正背全身）。**场景/道具**若已有可用概念分镜/概念图，可跳过模板生成，
   直接 `read_asset` 反推 prompt 后挂图；没有现成图时才生成单张概念图。
3. `upload_asset({ filename, dataBase64, mime, refId:"subject-state:<subjectId>/<state>" })` → 拿 `storageKey`。
   **默认只落 CAS，不建素材记录**：主体图属于主体库，进素材页就会变成「一张图两处显示」。只有要给片段当素材用的图才加 `toLibrary:true`。
4. `set_subject_image({ subjectId, storageKey, stateTag, prompt: 反推提示词, cover:true })` ——
   角色必须先 `set_subject_profile`（没写人设会被拒）；场景/道具可直接挂已有概念图；必须先 `read_asset` 看过这张图；`prompt` 是这张图反推出来的真实画面描述（不是愿望），不带 prompt 会被拒；第一张设为封面。
   **画布生图/改图落库时必须带 `origin`**：`{ model, steps, seed, aspect, megapixels, width, height, sourceStorageKey, jobId, rawPrompt }`，
   `rawPrompt` 是投喂模型的原始提示词（反推描述放 `prompt`），否则主体页看不出这张图是哪个模型、什么参数、从哪张原图改来的。
5. 关联片段：`link_subject_to_shot({ shotId, subjectId, state })` —— 写进片段 references，页面上才看得到缩略图；同一片段最多 9 张参考图。

> 只建主体不挂图 = 页面上是个空壳；只挂图不 link = 生成本段时用不上；把主体图也塞进素材库 = 同一张图两处出现。三步都要走，素材库那一步不要走。
