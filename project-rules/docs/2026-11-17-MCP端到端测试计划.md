# MCP 端到端测试计划（2026-11-17）

测试对象：`mcp-server`（数据根 `D:\ZeroExo`，ComfyUI `127.0.0.1:8188`）。
约束：**全程只用 MCP，不通过网页操作**；客户机上可能只有 MCP 源码，所以任何「必须开网页才能跑」的环节都算不合格。

## 一、测试目标

用户给的是一个结果目标，不是执行步骤：新建「测试项目」→ 出 5 张不同类型的图 → 基于这些图写一个简单剧本 → 把图变成主体（三视图）→ 拆出 4 段 5s 分镜（1-2 延续、3-4 延续）→ 4 段低分辨率 8 步视频 → 刷新后仍能看到图片与视频预览。

因此本次测试同时验证两件事：

1. **三件套是否真的存在**：剧本 + 主体（图生图三视图）+ 导演台规范分镜。
2. **MCP 是否会自己问齐缺的东西**：如果用户只说「帮我测一下」，MCP 是否会主动列出缺项（剧本文本、主体形态、图片比例/尺寸/步数、分镜时长、分辨率、步数），而不是闷头自己拍板或干脆卡住。不会问 = MCP 有缺陷。

## 三、测试计划（具体要生成什么）

### 3.1 画布图片（5 张，Qwen，25 步，最长边 ≤1024，比例各不相同）

| # | 类型 | 比例 | 尺寸 | 用途 |
|---|---|---|---|---|
| 1 | 人像（女性，优雅性感但不露骨） | 1:1 | 1024×1024 | 转成角色主体（三视图的参考图） |
| 2 | 动物（长毛猫） | 4:3 | 1024×768 | 验证不同比例的出图与缩略图 |
| 3 | 科幻（环形空间站夜景） | 16:9 | 1024×576 | 场景类素材，验证横构图 |
| 4 | 静物（咖啡杯与花） | 3:4 | 768×1024 | 竖构图 |
| 5 | 食物（拉面俯拍） | 9:16 | 576×1024 | 竖屏短视频可用比例 |

### 3.2 剧本（1 集，4 场，每场对应一段 5s）

以一晚三段式的简单故事串联五张图：女主在咖啡馆（人像/静物）→ 猫跳上窗台（动物）→ 夜晚街头抬头看见悬浮空间站（科幻）→ 街边面馆收尾（食物）。

要求：按 ZeroExo 标准剧本格式（场次 + 动作 + 台词），中文，纯中文文案，不写镜头号之外的导演备注进正文。

### 3.3 主体（走图生图，不是直接挂生活照）

| 主体 | 类型 | 来源 | 形态 |
|---|---|---|---|
| 女主 | 角色 | 第 1 张人像作为**上游输入图**，走 Qwen 图生图出三视图 | 三视图标准提示词（画面共 3 个：正面特写 / 正面全身 / 背面全身） |
| 街景夜景 | 场景 | 第 3 张科幻图 | 单张轴图（场景默认 single，不做宫格） |

要验的两条链路：

1. **画布图生图**：`edit_canvas_image` 传上游节点 id（或 storageKey）+ 编辑指令，产物必须是新节点，原图不动。
2. **网页是否自动建下游节点并连边**：上游图片节点 → 新的三视图节点，边上 pin 为 `image → prompt`；这条由网页的 MCP 任务订阅器落地，要求节点 id 幂等（`mcp_<taskId>_<i>`），刷新后不重复建。

挂正式主体图前必须 `read_asset` 看过成品、把画面反推成提示词，再 `set_subject_image`。

### 3.4 网页可见性（这次的重点，不是 MCP 独立黑箱）

MCP 只做「代理发起」：任务写进持久化任务表，网页订阅同一张表，把产物落到当前画布的节点上，用户在网页上直接看到预览与连线。因此验证点必须包含：

1. 未打开网页时提交，任务照常跑完（任务表 success）；
2. 打开（或刷新）项目页后，画布上出现对应节点、预览可见、图生图有上游连线；
3. 刷新不掉：节点 `storageKey` 已落画布 JSON；导演台视频每段 `previewKey` 与产物在任务表里都在。


### 3.4 导演台分镜（4 段，每段 5s）

| 段 | 对应场次 | 延续关系 |
|---|---|---|
| 1 | 咖啡馆 | 链头（不吃上一段尾帧） |
| 2 | 窗台猫 | 吃第 1 段尾帧 |
| 3 | 夜晚街头 | 链头（重新起链，不吃第 2 段） |
| 4 | 面馆 | 吃第 3 段尾帧 |

参数：低分辨率测试档（`scaleFactor` 取测试档、`refImageSize=match`）、8 步、24fps、每段 5s（帧数按 17k+5 吸附）。

流程纪律：`plan_continuity_edit` 先 dryRun 出「段/帧/秒/是否吃上一段」表 → 用户确认 → `confirm:true + userConfirmed:true`。

### 3.5 验证点

1. `get_script` 能读到 1 集正文与分块；`get_workbench` 能读到 4 段，且每段 `episodeId` 正确、时长 5s、双轨提示词非空。
2. 主体库 2 个主体，状态图 storageKey 为 CAS 键，`audit_subjects` 无「图没映射进状态」。
3. 分镜参考图槽位引用写成 `@PictureN`，`validate_project` 无 error。
4. 4 段视频生成完成后，`verify_output` 通过；每段 `media.guide` 有 guide 文件。
5. 刷新可见性（不看网页也能取证）：任务表里每段自己的 `previewKey`、`outputs` 与 `previewSegment` 都在，且 CAS/`assets/<pid>/tasks` 下文件真实存在 —— 这等价于「刷新后仍能拿到预览」。

## 四、MCP 会不会自己让我补东西（自查结论）

| 缺什么 | MCP 是否要求 Agent 问用户 | 依据 |
|---|---|---|
| 项目名 / 剧本文本 | 会 | `PIPELINE_STAGES` 阶段 1：列出缺什么，缺哪样问哪样，禁止编造 |
| 剧本格式 / 集数 / 是否英文源 | 会 | `preflight_import` 强制逐条问 |
| 图片模型、比例、尺寸、步数、张数 | 会 | skills `image-prompts`：用户必须明确说尺寸或明确同意推荐值，不要替他拍板；Qwen 默认 25 步 |
| 主体形态（角色三视图/场景单图/白底） | 会 | skills `subjects` 的 `renderMode` 说明 |
| 分镜段数、每段时长、是否拆段 | 会 | 阶段 4：用户没说「可以拆」不动手；时长逐项确认 |
| 导演台参数（分辨率/步数/引导帧/延续法） | 会 | 阶段 5 + `get_param_schema` |
| **用户只给一个结果目标时（例如「做 4 个测试片段」），空项目缺剧本/主体/图片这件事，MCP 会不会自动列清单** | **不会** | 阶段 1 只覆盖「用户给了原文但缺项目名」这种情形；没有「从零创作」入口，空项目只说目标时没有清单可依 |
| **画布图片生成到底能不能由 MCP 执行（口径）** | **自相矛盾** | `instructions` 说「生成任务由 MCP Task Broker 执行」，`module-specs` 阶段 5 却写「禁止提交任何真实 GPU 生成任务，真实生成走前端」。同一套文档两种口径 |

上面两条已列入本轮修复：统一口径为「画布图片由 MCP 执行、导演台视频由 ComfyUI 插件执行」；阶段 1 增加「从零创作」分支，先输出缺项清单再动手。
