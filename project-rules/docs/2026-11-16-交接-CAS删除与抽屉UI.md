### 1. 任务队列「删除后刷新必复活」= 两条链，不是插件推送

- **插件是纯被动执行器**：`comfyui-plugin/ComfyUI_ZeroExoNodes/__init__.py` 全文件只有 12 个 `@routes.*` 服务端端点（health/models/last-prompt/capabilities/jobs×3/tasks×4），**没有任何 outbound 请求或 websocket 推送**。用户怀疑的「插件把任务推回网页」不成立；真相是网页每次挂载/刷新主动 `listPluginTasks()` 拉插件任务表，把成功段重新落库。
- **复活链 A（队列展示）**：插件 `output/zeroexo/tasks/*.json` 永久留存 + 插件此前没有删除端点 → 队列每 3 秒全量同步又把终态任务塞回列表。
  修复：插件新增 `task_store.delete_task()` + `DELETE /zeroexo/v1/tasks/{task_id}`（进行中 409，终态删 JSON）；网页 `plugin-task-client.deletePluginTask()`；「清空已完成」先取 plugin 源 id → `clearFinished()` → 逐条真删。**插件侧需重启 ComfyUI 才加载新端点**；即使不重启，网页 `dismissed` 已挡住 `start/update/finish` 与 `applyPluginTasks`。
- **复活链 B（数据/媒体）**：`addAsset` 命中墓碑时旧代码 `return asset`（对象未落库），`history-autoland` 误判落库成功 → `landPluginSegment` 返回 storageKey → `onSegmentDone` 把版本与 `shot.media` 合并回工作台。
  修复：墓碑命中返回**哨兵** `{...asset, [TOMBSTONE_SKIP]: true}`（保留 `Promise<Asset>` 签名，避免 30+ 处既有调用/测试类型崩），导出 `isTombstoneSkip()`；`history-autoland`、`use-assets.addAsset`、`promoteAssetToScope` 三处改判哨兵 → 分别 `return null` / 不进列表 / 返回 null。
