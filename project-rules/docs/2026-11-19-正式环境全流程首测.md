# 正式环境首测：插件自更新 → 全流程（2026-11-19）

## 0. 目标与边界

1. **先验证云端 ComfyUI 插件的自更新能力**：GitHub `main` 上的 `comfyui-plugin/ComfyUI_ZeroExoNodes/manifest.json` 版本变化后，云端 ComfyUI 重启即按 sha256 自动覆盖插件文件，无需人工上传。
2. 再验证 **正式站点 + 正式 MCP + 云端 ComfyUI** 能否跑通完整链路：建项目 → 剧本 → 主体 → 场景图（多模型/多尺寸）→ 分镜片段 → 提示词质检 → **出片（视频生成）** → 产物回写。
3. 测试中发现的每个问题必须落「现象 / 根因 / 改动 / 复测结果」四段，不允许只写结论。

## 2. 测试素材（本轮固定）

- 题材：**经典迪士尼风格**（圆润造型、干净大色块、夸张表情、柔和体积光，禁止写实皮肤质感与颗粒）

- 场景图约束：**每个场景用一个不同图片模型（moss / krea2 / qwen 轮换）、不同分辨率、不同宽高比、不同 seed**，禁止统一参数

## 3. 用例与验收标准

### T0 插件自更新（前置，不通过则暂停后续）

- 步骤：记录云端插件当前版本与 `.update_state.json` → 推送一个更高版本到 GitHub `main` → 重启云端 ComfyUI → 读云端 `manifest.json` 与 `.update_state.json`
- 验收：
  - A1 云端 `manifest.json.version` 等于 GitHub `main` 的版本
  - A2 `.update_state.json.version` 同步更新
  - A3 云端 ComfyUI 日志出现 `[ZeroExo] self-update applied <version>`
  - A4 插件 HTTP `capabilities` 正常返回，节点未缺失
- 失败判定：版本不变、哈希校验失败、插件 import 异常。

### T1 项目与剧本

- 验收：3 集落盘、每集 4 场、场次标题均为 `script-scene-heading`、无空场；`version` 连续递增且每次写入有 baseVersion 校验。

### T2 主体库

- 验收：3 个角色都有完整人设（15 字段模板）、每个角色至少 1 张可用图、图像为单人/单主体、封面可读；缺图时生成流程能被门禁拦住。

### T3 场景图（10 张，参数必须互不相同）

- 验收：
  - B1 10 张全部落 CAS，`storageKey` 唯一
  - B2 每张记录 model / width×height / aspect / seed，且 10 张的参数组合无重复
  - B3 画布节点 `width/height` 与真实产物一致（面板值与出图一致）
  - B4 画面符合迪士尼风格（无写实皮肤、无胶片颗粒、无字幕/UI）

### T4 分镜片段

- 验收：3 集 × 4 段 = 12 段；每集编号 1..4 连续；每段时长 5s；无空片段；每段 `episodeId` 正确；片段引用主体槽位可解析。

### T5 提示词质检（检查模式）

- 验收：`review_shots` 对 12 段逐段返回 0–10 分；存在 error 时必须修复后才允许出片；低于 7 分不得进入 T6（除非用户明确 override 且留痕）。

### T6 出片（视频生成，本轮必须执行）

- 范围：至少完成 1 集 4 段端到端；其余集按时间允许继续
- 验收：
  - C1 每段产出一个视频文件，时长 5s（±1 帧），分辨率/比例符合请求
  - C2 第 2 段起吃到上一段尾帧/引导数据（`mode=initial|chain` 符合计划）
  - C3 任务表状态从 queued → success 全链路有记录；失败段必须有 error 原因
  - C4 产物落盘路径在数据根内，CAS/资产记录可查，画布/导演台可回看
  - C5 无 BGM、无字幕、无 UI 水印（按项目规范）

### T7 数据一致性与回写

- 验收：生成完成后 `paramValues` 与真实产物尺寸一致；刷新页面不丢节点/连线；导演台片段与资产记录互相可追溯；同一内容不产生重复资产。

### T8 异常与保护

- 验收：空图覆盖被拒绝；并发保存冲突有提示；删除片段有二次确认；服务离线时有明确原因文案。
