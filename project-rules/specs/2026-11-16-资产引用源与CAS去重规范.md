> 2026-11-16 用户要求：先把缓存去重机制修对、把各处引用源整理清楚，再动手。本文件即契约。

## 一、真相源分层（谁说了算）

| 层 | 位置 | 是真相吗 | 说明 |
|---|---|---|---|
| 文件字节 | `media/cas/<sha256>.<ext>` | **是**（唯一内容真相） | 存在即内容存在；不存在即内容缺失。索引 JSON 不得用来判断文件是否存在 |
| 资产记录 | `.lf/zeroexo/app_state/zeroexo%3Aassets.json` | **是**（唯一元数据真相） | 一条记录 = 一个可被引用的资产；id 稳定，`data.storageKey` 指向内容 |
| CAS 引用表 | `entities/cas_index.json` | 否 | 只存 `key → [{assetId, kind}]` 引用关系，用于引用归零判断；**不得**作为存在性判断源 |
| 片段版本缓存 | `projects/<pid>/entities/workbench.json` 的 `shot.cache.versions` | 否 | 是资产记录的**投影**（版本列表 = 指向该片段的资产记录集合），不得独立增删真相 |
| 画布节点 | `projects/<pid>/entities/canvas*.json` 节点 `data.storageKey` | 否 | 是对资产内容的引用，节点不持有字节 |
| 主体库容器 | `subjects.json` 中 `coverKey / states[].mediaKey` | 否 | 对资产内容的引用 |
| 引导帧 | `media/guides/gd_*.safetensors` | 是（内容） | 键 `guide:<id>.safetensors`，随片段/项目级联删除 |

**唯一写入者规则**：资产记录只能由 `addAssets` / `removeAssets` / `updateAsset` 改；workbench 只能由 `updateWorkbenchContainer` 改；引用表只能由 `attachRef` / `detachRef` 改。其他任何文件不得直接写这三个。

## 二、CAS 去重（put 语义）

```
put(bytes, kind) -> { id, cas:{hash,ext}, storageKey, bytes, mimeType, deduped:boolean }
```

1. 先算 sha256；`media/cas/<hash>.<ext>` 已存在则**不重写文件**，`deduped=true`。
2. 资产记录按 `storageKey` 全局查重：
   - 命中 → 返回**既有资产**（`deduped=true`），不新建记录；
   - 未命中 → 新建记录。
3. **任何情况下都返回句柄**，绝不返回空。上层不得把「去重命中」当成失败。
4. 同内容多记录是禁止的；但同内容不同引用方（画布节点 / 片段版本 / 主体封面）**各自可以指向同一条记录**。

## 三、删除职责矩阵

| 删除对象 | 必须发生 | 禁止发生 |
|---|---|---|
| 资产记录 | removeAssets（只删记录）；detachRef；引用归零才 unlink 文件 | 按 storageKey 级联删其他记录；按 shotId 摘版本 |
| 片段版本（历史删除） | 删对应资产记录 + **按 storageKey 全局**从所有 shot.cache.versions 摘除；摘空 → `clipState=placeholder`、`status=pending`、清 media/cache/guide | 只删记录不摘缓存（刷新必回来） |
| 项目 | guides → `assets/<pid>` → `projects/<pid>` 级联 | 从项目列表差集推目录 |
| 画布节点 | 只删节点，不动物业记录（内容可能被别处引用） | 顺手删资产 |

**「刷新又回来」的判定标准**：刷新后 `shot.cache.versions` 里不再出现被删 key，且资产记录不再包含该 id。两者缺一即未修好。

## 五、@ 引用（画布提示词）契约

1. 提示词保存结构：
   ```ts
   prompt: string            // 只含占位符 @@ref:1@@
   references: Array<{ assetId: string; kind: AssetKind; storageKey: string }>
   ```
2. 渲染时按 `references` 还原 chip（图标 + 缩略图 + 名称），**禁止**靠正则反解字符串。
3. 提交生成时：`references` 逐条转为上游输入（图片/视频/音频分别挂到对应输入槽），有 id 无文件 → 明确报错，不静默跳过。
4. 引用失效（记录被删/文件缺失）：chip 显示「引用失效」并可一键移除，**不得退化成纯文本**。
5. 刷新恢复：从节点 data 读 `references` + `prompt`，不得依赖会话内 blob URL。
