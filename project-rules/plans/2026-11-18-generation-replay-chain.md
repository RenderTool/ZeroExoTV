# C-06 生成引用链 / 同款 / 继续编辑（2026-11-18）

状态：**已拍板口径、实施中**（口径以本文件第 1 节为准）
范围：生成引用链持久化、只读子画布、同款、基于成图的继续编辑、出图尺寸、CAS 引用计数。

## 1. 术语与口径（用户定稿）

### 1.1 历史（生成引用链）
- 每次生成完成后，把**这一次生成自己的引用链**序列化持久化：
  - 本次生成用到的上游资产（参考图/视频/文本等）；
  - 本次产物；
  - 本次生成参数（提示词、模型、比例、尺寸、步数、seed 等）。
- 该记录**只读**：参数只读、引用资产只读，展示形式为**子画布**。
- 只保留本次生成自己的上游资产 + 产物，不复制无关节点，不重复保存整条主画布。
- 后续删除节点、做同款、继续编辑，**不得破坏已持久化的历史引用链**。
- 不使用“快照”这个临时概念命名；代码与文档统一叫“生成引用链（generation chain）”。

### 1.2 同款（链路复刻，不生成）
- 新建一个**空节点**；
- 拷贝被同款节点的参数（prompt / model / paramValues）；
- 拷贝其**上游引用资产**并建立连线；
- **不发起生成**。是否生成由用户点“生成”决定；
- 不改动原历史引用链。

### 1.3 继续编辑（明确的生成行为）
- 与同款相同的“新节点 + 参数 + 上游参考输入”复制；
- 位置**垂直避让**（同级向下顺排，不压节点、不接下游）；
- 然后**正式发起生成**。

## 2. 出图尺寸

- 多图输入 = 多图参考生成：**不存在“原图比例”选项**，出图比例/尺寸只由参数面板决定。
- 仅当**有且只有一个输入图片**时，才允许 `原图`（编辑/改图跟随原图尺寸），并可触发原图修改/编辑。
- 空节点切换比例时，节点框同步按统一 620×348 框等比变化。
- 参考图只做生成引导，不锁定出图比例（禁止 4:3 出 1:1、9:16 出 4:3）。

## 3. CAS 引用计数（必须一起设计，不能事后补）

风险：同款/继续编辑会创建新的引用节点；一条历史链也可能被多次复刻，CAS 引用计数会持续 +1。处理原则：

1. **不为引用节点重复创建资产记录**：引用节点只持有 `storageKey`，CAS 引用由既有扫描对账（`reconcileCasRefs` 的节点身份）补挂，不在交互路径手工 +1，避免同一节点被多路径重复计数。
2. **历史链自己持有引用**：每条持久化生成链登记一个独立引用身份（`kind='reconcile'`，身份 `chain:<chainId>`），覆盖该链的上游资产 + 产物。该身份随历史链永久保留，不因主画布节点删除而摘除；否则主画布清空后 CAS 归零会回收文件，历史链直接裂图。
3. **同款/继续编辑新建的节点属于新记录**：它们的 CAS 引用按新节点身份登记；删除这些节点时只摘自己这一条，**绝不动历史链的 `chain:<chainId>` 引用**。
4. **摘除边界沿用现有事故后规则**：只允许摘资产记录自己注册的 ref；扫描类与主体状态类永久保留；读取失败一律跳过摘除；物理回收只在索引 refs 归零时。
5. 需要拍板的点：历史链是否单独落 `chain:<chainId>` 引用（我建议落，否则历史不可靠）；如果落，同一条链被复刻多次时，历史引用只算 1 份，复刻节点各自算自己的，避免计数爆炸。

## 4. 实现拆分（确认后才动）

| 模块 | 改动 |
|---|---|
| 生成完成落库 | 序列化本次生成链（上游资产 + 产物 + 参数）到项目数据，登记 `chain:<id>` CAS 引用 |
| 只读子画布 | 读取该链，只读展示参数与引用资产；任意节点可点开自己的参数面板 |
| 同款 | 只建空节点 + 参数 + 上游引用连线，不生成 |
| 继续编辑 | 同款逻辑 + 垂直避让 + 发起生成 |
| 尺寸 | 单图才允许“原图”；多图隐藏；空节点切比例同步节点框 |
| CAS | 按第 3 节边界接入，不新增手工计数路径 |

## 5. 取舍

- **历史链落 CAS 引用**（建议）：历史稳定、裂图风险为零；代价是引用计数会长期占用磁盘，直到用户删除该历史记录。
- **不落 CAS 引用**：省空间；代价是主画布删光后历史图大概率被回收，直接违背“历史不能被破坏”。→ 不采纳。
- **同款自动生成**：已明确否定，同款不发起生成。
- **同款放在下游**：已明确否定，同级垂直避让。

## 7. 2026-11-18 补充：出图尺寸 352×352 根因与收口

实测插件 `/zeroexo/v1/last-prompt`：最新作业 `W=352 H=352`，而参数面板显示 4:3 / 1024×768，提示词「参考图1、参考图2：合照」。

根因（代码链路已核对）：

1. `LocalQwenParamForm` 的 `fallback` 写死为 4:3（1024×768），但**只用于显示**；当节点 `paramValues` 里没有 `width/height/size` 时不回写。
2. 生成时 `resolveRequestedImageSize(pv, fallback.size)` 落到 `buildTemplateParams` 的 `fallback.size`，而该值来自**节点框尺寸**（同级副本继承源节点 348×348 的展示框）。
3. `clampQwenEdge` 按 32 对齐，348 → 352，于是真实提交 352×352。

结论：参数面板的默认显示值与真实提交值不是同一份数据；节点框尺寸被误当成出图尺寸。

收口规则（硬性）：

- 出图尺寸的**唯一事实源**是 `paramValues`；节点框尺寸只用于画布展示，禁止参与生图请求。
- `paramValues` 没有显式尺寸时：有产物按 `naturalWidth/naturalHeight` 回退；无产物按面板默认 4:3（1024×768）回退并写回节点，保证「看到什么就生成什么」。
- 生成完成把真实出图 `width/height/size` 回写 `paramValues`，再次点击生成与上次一致。
- 同级副本（继续编辑）继承上游参数时，尺寸必须取源节点真实产物尺寸或显式参数，不取展示框。
- 任意比例的节点展示统一走 `fitMediaSize(IMAGE_FIT_BOX)`；历史链布局同样按此归一化，避免链路里产物明显偏小。

验收：面板选 4:3 → 作业 `EmptyLatentImage 1024×768`；选 9:16 → `576×1024`；同级副本在源节点正下方且上游连线一致。

### 8.2 收口（按此实现，不再另议）

**A. 提交时定链，不在完成后猜**

- 生成提交前，用真正提交的那份有序参考图列表生成 `inputAssets: [{ slot, nodeId, storageKey }]`，顺序即 `@图片1/@图片2…`。
- 同一时刻固化 `prompt / model / params（含 width/height/aspect/steps/seed）`。
- 结果返回后只做两件事：补产物 `storageKey`、写入资产记录 `generation.chain`。

**B. 链里只存可重建的东西**

- 媒体节点只存 `storageKey`（CAS），**剔除 `content` 的 blob:/dataURL**（blob 刷新即死，dataURL 会把记录撑爆）。
- 链节点 = 产物 + 真实参与本次生成的上游（参考图/文本提示词），边只留两端都在链内的。
- 展示时按 `storageKey` 解析媒体，永不依赖当次会话 URL。

**C. 历史打开只认存储，不猜**

- 有 `generation.chain` → 原样渲染，绝不用 live graph 补节点。
- 没有链 → 只渲染产物本身（`originNodeId` 还在就用它，删了就用记录里的 `storageKey/width/height/prompt/params` 造一个只读节点），**禁止拼入任何 live 节点**。
- 补一句明确提示（“该记录未保存生成引用链”），这是诚实降级，不是伪装成完整链。

**D. 旧记录一次性修复（迁移，不动别的东西）**

- 脚本按 `jobId` 拉 ComfyUI `/history`，解析 `LoadImage` 文件名里的 hash 前缀 → 匹配资产记录/CAS → 重建上游，读 `EmptyLatentImage` 宽高、`KSampler` seed/steps，写入 `generation.chain` 与 `generation.params`。
- 只补“缺失字段”，已有链的记录一条不改；写前备份 `zeroexo%3Aassets.json`。
- 解析不到作业的记录保持无链降级，不猜。

**E. 同款 / 继续编辑读链，不读 live graph**

- 同款：按链建空节点 + 参数 + 上游引用连线，不生成。
- 继续编辑：同款逻辑 + 源节点正下方垂直新建 + 正式生成。
- 两者都不改动原历史链；新节点的 CAS 引用各自登记，历史链的 `chain:<assetId>` 永久保留。
