# 生成任务下沉 ComfyUI 插件（本地链路重构）

日期：2026-11-16
范围：**只改本地网页 + 本地 ComfyUI 插件 + 本地 MCP，不动线上环境。**

## 背景 / 结论

当前把任务事实源和执行者放在 MCP：
- MCP 持有任务表、lease、轮询、落库；ComfyUI 插件只是被动执行一批；
- 关网页没事，但**关 MCP / 重启 MCP**会中断任务推进；
- 任务超时、SSE 挂起、刷新丢状态都发生在 MCP 这一层。

用户拍板的新结构：

> MCP 应专注“操作网页 / 查任务状态”；生成任务交给 ComfyUI 插件服务自己持有。
> 插件一直开着，关网页、关 MCP 都不应中断生成。

## 职责边界

| 层 | 负责 | 不负责 |
|---|---|---|
| ComfyUI 插件 | 持久任务队列、批次/段状态、串行执行、段间 guide 自链、成品/引导文件、任务查询/取消、SSE/轮询 | 不写 projects/*、workbench、CAS、资产记录 |
| 网页 | 提交任务到插件、订阅/轮询任务、把已完成段幂等落库到项目（CAS/资产/shot.cache/media/预览）、刷新恢复 | 不执行生成、不做跨进程任务队列 |
| MCP | 项目数据操作、任务状态代理查询（读插件任务）、给 Agent 的导演台/素材工具 | 不再持有/执行生成任务，不再做 lease 轮询执行器 |

## 插件侧

### 持久化

- 任务文件：`<ComfyUI>/output/zeroexo/tasks/<taskId>.json`
- 任务形状（与当前 broker 任务对齐，便于网页复用）：
  - `taskId / projectId / kind / state / title / createdAt / updatedAt`
  - `request`（selectedIds/episode/params）
  - `segments[]`：`index / shotId / state / prompt / guide / progress / previewPath / outputs / error`
  - `doneCount / totalCount / currentSegment / error`
- 每次状态变化原子写（temp + rename）；文件存在即任务存在。
- 启动时扫描 `tasks/*.json`：
  - `queued`：重新入队；
  - `running` 且子 prompt 已不在 ComfyUI 队列/历史：标 `interrupted`，保留已完成段；
  - 已完成段绝不回滚。
- 任务/成品文件都在插件目录，插件服务活着就继续跑。

### 接口

- `POST /zeroexo/v1/tasks`：创建并持久化任务，立即入队
- `GET /zeroexo/v1/tasks?projectId=`：任务列表
- `GET /zeroexo/v1/tasks/{id}`：任务详情（含每段状态/产物/guide）
- `POST /zeroexo/v1/tasks/{id}/cancel`：只取消未开始段；正在生成的段可配置“先收尾再停”
- `GET /zeroexo/v1/tasks/events?projectId=`：SSE（断线由网页轮询兜底）
- 复用现有 `/zeroexo/v1/jobs/*` 作为执行层内部接口，不再作为网页主入口。

### 执行

- 复用现有 `BATCH_QUEUE` / `_batch_worker`，但 queued/running 状态落盘；
- 每段完成：写 outputs/guide/previewPath，更新任务文件；
- guide 链：批次内 `initial/chain/none`，不依赖 MCP/网页；
- 取消：只标未开始段；已完成段保留。

## 网页侧

- 新增 `plugin-task-client.ts`：直连 ComfyUI base（本地默认 `http://127.0.0.1:8188`），提交/查询/取消/订阅。
- 导演台 `useDirectorTask` 改为插件任务源；刷新后按 projectId 拉列表恢复。
- 每段完成时，网页做幂等落库：
  - 下载成品 → CAS → 资产记录（originSource=director，originNodeId=shotId，guide）
  - `shot.cache` 追加版本、选中最新、`media`/`firstFrameKey` 投影
  - 预览用插件 `previewPath`（成品末帧）
- 落库失败可重试；同一 storageKey/版本 id 幂等，不重复建记录。
- 网页关闭期间插件继续跑；重开网页拉任务详情，把所有已完成段补落库。
- 任务队列抽屉直接展示插件任务，取消调插件接口。

## MCP 侧

- 删除/停用 `src/broker/executor.ts` 的生成执行与 lease 轮询（保留文件前先迁走可复用纯函数）。
- `list_generation_tasks/get_generation_task/cancel_generation_task` 改为代理插件 HTTP 任务接口（本地 ComfyUI base）。
- `request_director_run` 只负责把“要生成什么”提交给插件，不执行、不轮询落库。
- 项目落库仍可由网页完成；MCP 不作为生成链路必需进程。

## 迁移顺序

1. 插件持久任务表 + 任务接口 + 启动恢复；用 curl 验证关网页/关 MCP 后仍继续。
2. 网页直连插件提交/订阅；复用现有 `useDirectorTask` 状态映射。
3. 网页幂等落库（把 MCP `landVideo` 逻辑迁到前端，或共享纯函数）。
4. MCP 任务工具改代理；停用 broker 执行器；删旧 lease/任务表。
5. 本地回归：刷新/关网页/关 MCP/插件重启/取消/失败/多开。

## 验收

- 发起 3 段任务后关闭网页 2 分钟再打开：进度继续、已完成段可播、历史有记录。
- 关闭本地 MCP 后任务继续；重开 MCP 能查到同一任务。
- 取消：已完成段保留，未开始段取消。
- 插件重启：已完成段保留，未完成段标中断，不丢文件。
- guide：段 2 接段 1 当前版本，段 3 接段 2；与网页/MCP 是否在线无关。
- 刷新后每段预览/时长/版本正确，不重复落库。

## 进展（2026-11-16）

- 新增 `comfyui-plugin/ComfyUI_ZeroExoNodes/task_store.py`：任务目录、原子写、列表/读取、running→interrupted。
- 插件批次状态现在持久化到 `output/zeroexo/tasks/<taskId>.json`：创建、开始、每段开始/完成、取消、结束都写盘。
- 新增插件任务接口：
  - `POST /zeroexo/v1/tasks`
  - `GET /zeroexo/v1/tasks?projectId=`
  - `GET /zeroexo/v1/tasks/{id}`
  - `POST /zeroexo/v1/tasks/{id}/cancel`
- 插件首次访问会恢复任务：queued 重新入队；running 标 interrupted，已完成段保留。
- 新增 `director-plugin-payload.ts`：网页侧纯函数组装批次（连续 run、起始 guide/段内 chain、帧数/尺寸/参数），单测覆盖 3,4+6,7、首段无 guide、显式 guide 优先。
- 新增 `plugin-task-client.ts`：网页直连插件的 submit/list/get/cancel 客户端（尚未接入 `useDirectorTask`）。

- `workbench-tab-content` 已切到插件 hook；启动任务时用 `buildDirectorBatchPayload` 组装段。
- 新增 `plugin-task-landing.ts`：插件 output 绝对路径 → `/view` 下载 → CAS/资产记录（导演台来源）。
- 新增 `mcp-server/src/broker/plugin-client.ts`：MCP 代理插件任务列表/详情/取消。
- `list_generation_tasks/get_generation_task/cancel_generation_task` 已改为插件代理。
- MCP 源码删除 `startBroker()` 启动（导演台/画布生成不再由 MCP 执行）；本地运行进程仍是旧版，未重启。
- `request_director_run` 已改为**拒绝提交**：提示由网页发起，MCP 只查询插件任务；`run_generation` 同样停用。
