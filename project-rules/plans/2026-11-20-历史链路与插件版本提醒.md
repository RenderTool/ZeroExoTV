# C-08 本轮线上可用性问题批量（2026-11-20）

> 用户口径：需求先落 Plan 再动代码。本 Plan 汇总 2026-11-19 22:00 → 2026-11-20 00:xx 的报障与拍板项。
> 一次只推进一个优先级；本轮先解决 **P0 历史链路**，其余按序。

## 1. 口径（先定，再改代码）

- **历史链路 = 提示词 + 素材 + 结果**：任何生成历史（分镜/导演台片段、画布图片、画布视频）打开只读子画布时，都必须是「提示词节点 →（素材节点）→ 产物节点」的链路形态，不允许只丢一个产物节点。
- 老记录没存 `generation.chain` 时，用「资产记录里的 prompt + 来源片段（导演台 shot）的 references」合成；提示词节点的正文呈现与分镜保持一致（逐行包 `<p>`，避免文本节点富文本 HTML 把纯字符串折成一行），不做二次改写。
- 图链路要有可见连线：素材（image 输出 `image` pin）与提示词（text 输出 `output` pin）都连到产物输入 `prompt` pin。
- 只读快照只增不减：旧快照缺提示词/缺连线时按当前规则重建同一 cid，不新建第二个画布。

## 2. 条目（现象 → 根因 → 改动 → 验收）

### P0-1 历史链路缺提示词与素材（用户连报 1 天）
- 现象：分镜/片段历史打开只读子画布只有一个产物节点；dock 显示「这条历史记录没有提示词（旧版本生成）」；无连线。
- 根因：`HistoryGroup.openChainCanvas` 只在 `generation.chain.nodes` 存在时渲染链路；无 chain 老记录只造产物节点；存量快照 `edges=[]`，且复用判据不含 prompt，导致旧坏快照永远被复用。
- 改动：无 chain 时按 `originNodeId` 找导演台 shot（references + imagePrompt/videoPrompt）或资产 `sourceStorageKey` 合成「提示词节点 + 素材节点 + 产物」并补 pin 正确连线；有 chain 但 `edges` 为空时按节点角色补线；复用判据（dataSig）加入 prompt；产物节点缺 prompt 时用记录补齐。
- 验收：打开片段 3/4（`lzmpUdwVOH_FMNnPtYRvN`、`ymXeoHAYFmdmMQ6MGAHMp`）历史 → 看到提示词节点 + 定妆/概念图节点 + 视频节点 + 连线；dock 能读到完整提示词。

### P0-2 画布生成的视频也要链路
- 现象：画布直接生成的视频历史同样只有一个节点。
- 改动：同一套合成逻辑对 `originSource=canvas` 生效，参考图取 `generation.sourceStorageKey`；没有参考图时至少「提示词 → 产物」两节点。
- 验收：任一画布视频历史都显示提示词节点 + 产物节点。

### P0-4 同片段多版本被认成同一条链路（2026-11-20 报障）
- 现象：分镜历史里「片段 1 第 1~5 版」五张卡打开提示词都是同一条；还会弹「子画布文件已被外部修改」。
- 根因：链路快照 cid 只由节点 id 集合算哈希；同片段的各版本链路节点 id 完全相同（`chain_prompt` / `chain_input_N` / `seg-xxx`），于是全部落回同一份快照，后建的覆盖先建的，打开别版就弹冲突。
- 改动：cid 追加资产记录 id（每个产物一份只读快照）；页签标题带版本号（`… · 第 N 版`），不再都叫「片段 1」。
- 验收：依次打开第 1/3/5 版，各自显示本版提示词与素材，不再互相覆盖、不弹外部修改冲突。

### P1-1 顶栏「历史版本」按钮位置
- 现象：按钮挨着左上 LOGO 区，用户要求放右上角工具组。
- 改动：`TopBar` 增 `rightTools` 槽位，`CanvasHistoryButton` 移入右侧工具组。
- 验收：右上角设置/服务组旁可见历史版本图标，左侧不再出现。

### P1-2 云端插件无法自动更新 → 连通后提醒
- 现象：云端实例插件不会自更新，旧版本可能长期在跑。
- 改动：新增 `plugin-version.ts`（`OFFICIAL_PLUGIN_VERSION` 与 `PLUGIN_VERSION` 同步）、`testEndpointConnection` 的 zeroexo 分支带 `pluginVersion/pluginOutdated`；面板一行提示 + 每个「地址+版本」一次性 toast。
- 验收：云端 0.1.0 连上时提示「低于官方 0.1.1，请手动替换插件后重启」；0.1.1 不再提示。

### P0-3 引导双重兜底（2026-11-19 拍板，已实现待验收）
- 口径：云端 output 账户制持久；提交前先查云端 `output/zeroexo/guides/<id>.safetensors`（支持 `?sha256=` 内容校验），缺了再用本地 `media/guides` 上传；两边都没有才报错。
- 已落：插件 `GET/POST /zeroexo/v1/guides/{id}`（0.1.1，未部署云端）；MCP `ensureComfyGuide`；网页 `ensureGuidesOnComfy`。
- 待验收：云端实例换上 0.1.1 插件后，断开本地网络也能续接已有引导。

### P1-3 任务队列页「暂无任务」不说原因
- 现象：发起多条生成后队列页仍空，只显示「暂无任务」，用户判断该页形同虚设。
- 根因：任务事实源在云端插件（`/zeroexo/v1/tasks`），插件 404/未连接时列表必然为空，但空态不区分「真没有任务」与「读不到」。
- 改动：空态在 `connected=false` 时补一行「ComfyUI 未连接，任务列表暂时读不到；连上后自动同步（不影响发起生成）」；不拦生成、不代替用户判断。
- 验收：断连时打开队列页看到该说明；连上后有空任务时恢复「暂无任务」。

### P1-4 未启动 MCP 时整站变成离线门页面（2026-11-20 报障）
- 现象：MCP（8790）没启动，打开网页直接落到「本地数据服务离线」整页门，主题色也不对（黑底浅字看不清）。
- 根因：`dataRootState()` 在 `dataRootExpectsService()` 为真时无条件返回 `service-offline`，即使浏览器里还有已授权目录句柄；该门页面写死浅色文字、也没用主题 token。
- 改动：服务离线时先尝试浏览器已授权句柄（持久权限 `granted` 即按浏览器目录打开，页面照常用，MCP 相关能力由各自面板提示）；确实没有可用句柄才落离线门。离线门改用 `theme.canvas.background` / `theme.toolbar.text` / `textMuted`，明暗都可读。
- 验收：不启动 MCP 直接打开网页 → 能进项目列表并正常读写；只有既无服务又无目录授权时才出现离线门，且明暗主题下文字均清晰。

### P1-5 ComfyUI 运行时心跳（2026-11-20 报障：挂 2 小时才发现显存炸了）
- 现象：ComfyUI 进程崩溃/显存 OOM 后任务一直挂起，网页不报警，用户开着页面等两小时。
- 根因：只有任务记录（`/zeroexo/v1/tasks/{id}`）轮询，没有进程级心跳判断；轮询失败只给「连接已断开」，不提示具体可能原因。
- 改动：任务轮询失败时追加 `GET /zeroexo/v1/health` 短超时（5s）心跳探活；连续两次心跳失败 → 队列行标「ComfyUI 无响应」+ 一次性明确提示「进程崩溃或显存不足（OOM），看 ComfyUI 控制台报错，重启后重试该段」；心跳恢复自动清零。
- 验收：停掉 ComfyUI 进程后 ~10 秒内出现该警告；恢复进程后不再复报。

### P1-6 参考图上传失败只说「上传失败」+ 主体状态名重复（2026-11-20 报障）
- 现象：生成时报「参考图上传失败：中州驿站庭院·中州驿站庭院 · 状态4」；名称把主体名重复拼了两遍；错误信息看不出到底是 ComfyUI 没连上还是图有问题。
- 根因：① 主体状态默认名已是「<主体名> · 状态N」（`buildDefaultStateName`），插槽标题又拼了一次 `item.name·stateName`；② `attachDirectorReferenceImages` 上传前没有探活，`/upload/image` 失败统一抛「参考图上传失败」，用户无法区分「ComfyUI 实例已停（404）/ 网络不通 / 图读取失败」。
- 改动：新增 `subjectStateDisplayName()` 去重前缀，导演台插槽与槽位选择器统一使用；参考图上传前先 `GET /system_stats` 探活，不通直接报「ComfyUI 连不上（地址）：实例已停止或地址失效，先在连接面板测试通过再生成」；单个槽位上传失败时把槽号 + 文件名 + 失败原因一起报出。
- 验收：状态图在插槽里显示「中州驿站庭院 · 状态4」不重复；ComfyUI 未连时生成直接给出可执行提示，而不是笼统的「参考图上传失败」。

### P1-7 主体状态「原图」档位不可选 / 选了不生效（2026-11-20 报障）
- 现象：主体状态页引用状态图（或继承基础状态）后，尺寸档位的「原图」仍灰掉；即便可选，提交也永远按 custom 尺寸。
- 根因：① UI 只数显式 `referenceKeys`，漏了「继承基础状态」的封面图（派生状态默认 `useBaseRef=true`，实际已有 1 张输入图）；② 底栏 `sizeMode` 写死 `custom`，`genParams` 也没有 `sizeMode` 字段，原图选项没有落地路径。
- 改动：`SubjectGenParams` 增加 `sizeMode?: 'custom' | 'source'`；`resolveSubjectGenParams` 透出；底栏用真实有效参考图数（显式引用 + 基础状态去重）判断可用性；`onParamsChange` 把原图写入 `genParams.sizeMode`；生成提交把 `params.sizeMode` 原样传给 Qwen（真有且仅有一张输入图时才跟随原图尺寸）。
- 验收：引用 1 张状态图/继承基础状态时「原图」可选；切到原图后提交尺寸 = 参考图真实宽高；多图参考时仍不可选。

### P1-8 切换顶部页签会改掉抽屉选中的分组（2026-11-20 报障）
- 现象：在画布 / 分镜 / 剧本之间切换时，右侧抽屉当前分组（以及搜索筛选里刚挑中的东西）被自动改掉。
- 根因：抽屉分组按**模块**分别记忆（`groupByModule`），切模块就换成该模块的上次分组/默认分组；另有一条「切模块即清搜索词」的 effect。
- 改动：抽屉只保留**一个**当前分组，跨模块沿用；仅当该分组在当前模块不可挂载（层级 / 本剧信息）时回落到第一个可见分组（必要跳转）；切模块不再清空搜索词。
- 验收：在画布选中「主体」分组 → 切到分镜/剧本 → 抽屉仍是「主体」；切回画布仍是同一分组与同一搜索词。

### P1-9 画布生成中打开节点提示词变空（2026-11-20 报障）
- 现象：画布图片节点生成中（采样 5/25）打开底栏，提示词框是空的（0 字），参数摘要回默认。
- 根因：① 生成开始时若走占位节点链路，占位节点只写 `status/generationType`，没有 `prompt/model/paramValues`，而底栏按「当前选中节点 data」取值，选中切到占位节点后即变空；② 底栏初值只读 `data.prompt`，节点 `data.prompt` 被清或尚未回写时没有回退来源。
- 改动：占位节点把本次提交的 `prompt/model/paramValues`（含 size/quality/count/seconds）一起写入；`visibleNodePrompt` 增加回退链 `data.prompt → data.generation.prompt → data.paramValues.prompt`。
- 验收：生成中打开底栏仍显示本次提示词与同一套参数；生成取消/失败后提示词仍在，可直接改后重跑。

### P1-10 主体/状态引用失效要有片段级感叹号角标（2026-11-20 报障）
- 现象：只在引用槽里提示失效，底部片段卡没有任何标记，用户要逐段点进去才知道哪段有问题。
- 改动：`detectStaleRefs` 已把失效写进 `references[].stale`；这里汇总到片段级 `TimelineClipData.stale`（broken 优先，其次 warn），时间轴卡片左上角渲染感叹号角标（broken 红 / warn 橙），tooltip 带具体原因；引用修好后 stale 清空 → 角标自动消失。
- 验收：主体状态被删的那一段，卡片左上角出现红色感叹号；把引用换成新状态图或移除后，角标消失，无需刷新。
