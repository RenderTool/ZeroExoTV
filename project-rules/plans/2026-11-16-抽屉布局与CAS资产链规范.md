# 抽屉列表页布局规范 + CAS 资产链重构

> 立项原因：2026-11-16 连续几轮 UI 返工（搜索条被挤、卡片随抽屉变宽变小、间距各页不一），以及「上传完成但列表不显示」「删除刷新又回来」两类数据问题，根因都不是单点 bug，而是**缺少一份可执行规范**。本文件即该规范与实施计划，后续改动必须引用本文件，不允许再凭手感改。

## 一、问题事实（已实测）

| 现象 | 证据 | 根因 |
|---|---|---|
| 上传完成但列表空 | `zeroexo%3Aassets.json` 写入时间 18:17:52，但 70 条记录里最新 `createdAt` 仍是 09:56 | `stageCasUpload`/`addAssets` 命中已有 storageKey 时**返回空**，调用方以为没建记录，列表不刷新 |
| 「所有文件均不支持上传」 | 8790 在线、`D:\Test` 可写、png/jpg 在白名单内 | 上传链路三种结局（新建/去重/失败）在 UI 上没区分，旧代码统一压成一句格式提示 |
| 删除刷新又回来 | 资产记录 `originNodeId=seg-1794769295888-3mui`，工作台只有 `seg-1794772571410-4p1a` / `seg-1794772596357-qa05` | 摘版本只看 shotId 永远匹配不上；已改为按 storageKey 全局摘除 |
| 卡片随抽屉变宽变小 | `gridTemplateColumns: repeat(auto-fill, minmax(160px, 1fr))` | 列宽用 `1fr` 会无限拉伸/增列；卡片宽度必须有上限 |
| 搜索条被压成缝 | ToolbarRow 单行 `nowrap` + 多个固定宽下拉 | 搜索框没有最小宽，固定控件优先抢空间 |

## 二、布局规范（抽屉列表页唯一口径）

顺序固定：**标题（有 Tab 则不出现）→ Tab → 搜索栏 + 批量操作 → 分类标签 → 内容区**。

| 元素 | 规则 |
|---|---|
| 页面左右内边距 | 统一 20px，所有行、网格、常驻提示条都对齐这条线 |
| 标题 | `padding: 10px 20px 0`，字号 13 / 字重 600，**不出下边框** |
| Tab 行 | `padding: 8px 20px 0`；有 Tab 的页面不得再渲染标题 |
| 搜索行 | `ToolbarRow`（`8px 20px 10px`）；搜索：`flex:1`、`min-width:140`、高 26；下拉固定 120；多选按钮 32；放不下时横向滚动，**禁止把搜索压到 0** |
| 分类标签行 | `padding-top: 0`，与搜索行间距 10；历史页的片段筛选并入搜索行，不再单独占行 |
| 上传/添加主操作 | 位于内容区上方：`padding: 12px 20px`，全宽虚线 tile |
| 内容网格 | `padding: 12px 20px 16px`；`gap: 16`；列宽 `minmax(220px, 260px)`（**必须有上限，抽屉变宽只增列不缩卡**） |
| 常驻提示条 | `position: sticky; bottom: 0`，左右 20，上下 8，半透明底 + 模糊 |
| 卡片 | 封面 `aspect-ratio: 16/9`；名称 12/500；元信息 11；操作按钮 hover 才出现；多选时右上角勾选框 |
| 分割线 | 侧边栏模块分组：某模块独有分组加 `dividerBefore`；抽屉面板头部**不加**横向分割线 |

## 三、CAS 资产链规范

采用社区 CAS 三条硬规则（不引入第三方框架，理由见 §3.3）：

1. **put 幂等**：`stageCasUpload(file) → { id, cas, storageKey, bytes, mimeType }`。hash 已存在也必须返回既有句柄，**绝不返回空**。
2. **文件系统即索引**：`media/cas/<hash>.<ext>` 是否存在就是唯一事实；`entities/cas_index.json` 只保存**引用关系**（`key → [{assetId, kind}]`），不得作为文件存在性判断源。
3. **attach/detach 单一入口**：只有 `cas-store` 的 `attachRef` / `detachRef` 能改引用；引用归零才 unlink，GC 走显式 sweep，禁止任何「按扫描差集摘除」。

### 3.1 上传结果三态

`addAssets` 返回 `{ created: Asset[], deduped: Asset[] }`；UI 分别提示：
- `created.length > 0` → 「已上传 N 项」
- 仅 `deduped` → 「N 项内容已存在，已复用原有资产」（**同时刷新列表**）
- 抛出错误 → 显示真实原因（未授权 / 服务离线 / 格式 / 体积）

### 3.2 与删除链路的关系

删除资产记录时：detachRef → 引用归零才删文件；同时按 storageKey 全局摘 `shot.cache.versions`，摘空则片段回 `placeholder/pending`、`status=pending`，完成角标同步变。

### 3.3 为什么不用第三方 CAS 包

候选包（`content-addressable-storage`、`abstract-blob-store`、`ipfs-unixfs`）均假设「Node 进程独占存储目录」；本项目是**浏览器直连 HTTP 文件服务（8790）+ MCP 共用同一数据根**的双端模型，套框架会引入第二个存储入口，与「单一数据根」冲突。因此只复用成熟原语：`crypto.subtle`/`hash-wasm` 算 sha256、原子写用「临时文件 + rename」。若后续把 CAS 收进 fs-server 进程，可评估 `lmdb` 做引用表。

## 四、实施步骤

1. `stageCasUpload` 幂等化（命中返回既有句柄）。
2. `addAssets` 返回 `created/deduped`；抽屉、@ 面板、资产库三处上传入口改三态提示。
3. 抽屉四页套用 §二 标尺：公共资产 / 主体 / 历史 / 画布结构，逐页删掉自定义 padding。
4. 网格列宽改 `minmax(220px, 260px)`；搜索框 `min-width:140`。
5. @ 引用结构化：提示词存 `references: [{assetId, kind, storageKey}]`，文本只留占位符，缺资产显式显示「引用失效」。
6. 三方资产作用域统一：抽屉 / @ 面板 / 画布都调用同一个 `selectAssetsByScope(scope)`。

## 五、验收

- typecheck `EXIT=0`；上传同一张图两次：第一次「已上传 1 项」且列表出现，第二次「已存在，已复用」且列表仍显示该资产。
- 抽屉拉到最宽：卡片宽度不超过 260，不出现单卡巨幅；拉到最窄：搜索框不小于 140 且可横向滚动。
- 删除历史封面 → 刷新 → 不回来；片段回空态；完成角标变「未生成」。
- 四页的标题、搜索、分类、内容左边缘在同一竖线上。
