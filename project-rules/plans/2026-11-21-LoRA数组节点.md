# C-12 LoRA 改成「数组节点」：模板里能看见的串联（2026-11-21）

## 1. 用户口径（原话）

> reference_video.json 我的意思是这个底稿这里为什么不直接改成数组节点？？？？
> 我让你写一个节点代替原来的单节点！！

结论：不要「运行时删节点、造 `zx_lora_*` 链」这种看不见的做法，要在**模板底稿里就是一个节点**，这个节点自己吃一份 LoRA 数组、内部顺序串联。

## 2. 为什么现在模板只有一个节点

ComfyUI 核心的 `LoraLoaderModelOnly` 一实例只吃一个 `lora_name` + 一个 `strength_model`，没有数组类。当前实现是运行时把 `25` 号节点删掉、生成 `zx_lora_0..n` 再接线——图变了但底稿没变，所以 UI 打开永远只看到一个节点。

## 3. 方案：插件自定义节点 `ZeroExoLoraChain`

- 新增 `comfyui-plugin/ComfyUI_ZeroExoNodes/lora_chain.py`
- `INPUT_TYPES`：`model`（MODEL）+ `loras`（STRING, multiline）
- 输出 `MODEL`，`FUNCTION = apply`
- `loras` 文本解析（两种都认，顺序即串联顺序）：
  - JSON 数组：`[{"name":"a.safetensors","strength":0.8}, ...]`
  - 逐行：`a.safetensors | 0.8`（`|` 或 `,` 或 tab 分隔；`#` 开头为注释）
  - 空 / 只有注释 → **原样透传 model**（不勾 LoRA 不能断链）
- 逐条 `load_torch_file` + `comfy.sd.load_lora_for_models(model, None, lora, strength, 0)`；
  `strength` 夹 0–2；文件不在 `folder_paths.get_filename_list("loras")` 里 → `RuntimeError`，报缺失文件名 + 当前可用清单前若干条（不静默跳过）。
- 结果缓存：同一 `lora_name+mtime` 的权重字典进程内复用（dict，带简单上限），避免多段批次重复读盘。

## 4. 模板改造

`templates/reference_video.json` 的 `25` 号节点：`LoraLoaderModelOnly` → `ZeroExoLoraChain`，保留 id `25`（下游 `12` 的 `["25",0]` 不动），输入变成：

```json
"25": {
  "class_type": "ZeroExoLoraChain",
  "inputs": {
    "model": ["45:66", 0],
    "loras": "# 每行一条：文件名 | 强度（0–2），顺序 = 串联顺序\nminimax_h3_ref2v_turbo_8step_v1.0_768p_comfyui_bf16.safetensors | 1.0"
  }
}
```

`prune_model_chain` 不受影响（它只改 `45:66` 的消费者，`25` 就是消费者）。

## 5. `apply_lora_chain` 改造

- 优先路径：图里有 `ZeroExoLoraChain` 节点 → 只给它 `inputs["loras"]` 赋文本，**图结构零改动**（不再新增/删除节点）。
- 兼容路径：图里没有该节点（老模板 / 老插件产物）→ 保持 0.1.3 的「单条改节点、N 条造链」逻辑不动，避免老工程炸。
- `_resolve_loras` 的校验逻辑保留（宁可提交前报错，不要跑起来才发现）。

## 8. 风险

- 低于 0.1.4 的实例/老工作流不认识这个 class，会红节点 —— 模板与节点同批发布，云端部署前不要单独发模板。
- 节点内循环加载会一次性把 N 个 LoRA 权重驻留显存，4 条以上要提示（网页上限仍是 4）。
