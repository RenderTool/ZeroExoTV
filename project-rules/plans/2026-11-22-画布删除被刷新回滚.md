# C-24 画布删除节点后立刻刷新又回来

## 用户报障（2026-11-22）

> 现在画布是不让删东西嘛？为什么我删除节点后又回来了？
> 我删除后直接刷新页面就回来了

## 根因（已定位，不是猜）

主画布删除本身是**物理移除**（`ReplaceSceneCommand` / `RemoveNodeCommand`，`use-editor-state.ts:1077`、`use-node-actions.ts:155`），
问题在落盘时序：

1. `PersistencePlugin` 对每次 `CommandEvents.EXECUTED` 只做 `scheduleSave()`：
   `debounceMs = 400`（`index.ts:144`）→ 到期后还要 `requestIdleCallback(..., {timeout: 2000})`（`index.ts:491-505`）。
2. 全仓没有任何 `beforeunload` / `pagehide` 的落盘 flush（grep `pagehide|beforeunload` 在 src 与 packages 均为空），
   `save()` 只在 Agent 批量结束、文档切换时被调用。
3. 于是「删完 → 立刻刷新」时，这份删除快照还躺在 400ms 防抖定时器/空闲回调里，
   刷新把定时器直接丢掉，`load()` 读到的仍是**删前那份 graph** → 节点回来。

一句话：不是不让删，是**删除没来得及落盘就被刷新截断**，加载回退到旧快照。

## 修法（三层，都围绕「刷新不能丢删」）

1. **同步墓碑兜底**（新增 `node-tombstones.ts`）：命令执行时对比上一版节点 id 集合，
   把「消失的 id」**同步**写进 `localStorage`（不经 IndexedDB）；`load()` 先把这些 id 从磁盘图里剔掉。
   `UNDONE/REDONE` 会把重新出现的 id 从墓碑移除（撤销照常可用）；写盘成功即清墓碑。
2. **删除即落盘**：删除路径执行完后立刻 `persistence.save()`（跳过防抖），缩短丢失窗口。
3. **离页 flush**：`pagehide` / `visibilitychange(hidden)` 时清定时器并立刻写一次。

## 不做什么

- 不动删除语义（仍然物理删、仍可撤销、仍禁止删 `status==='loading'` 的节点）。
- 不改 400ms 防抖本身（它是性能护栏）。
- 墓碑只存 id 不存正文，上限 500 条，防 localStorage 膨胀。

## 验收

- 单测：墓碑同步读写 / 撤销回填清除 / 上限裁剪；load 时剔除墓碑 id（含其边）。
- 手测：删节点 → 立刻刷新 → 节点不回来；撤销删除 → 刷新后仍在。
