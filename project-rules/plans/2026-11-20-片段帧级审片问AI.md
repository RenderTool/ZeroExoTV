# C-09 片段帧级审片：暂停定格 → 问AI（含时段多帧）

> 状态：**SPEC 待审核，未动一行代码**。落库 2026-11-20，目标版本 0.4.34。
> 用户原话（原文保留）：「暂停后右上角要出现一个问AI，把这一整截图 + 本帧具体时间 + 本片段现状发给 AI，因为很可能这个镜头出问题了」「选中有问题的时间段让 AI 微调提示词」「N 帧截图压缩让 LLM 查看？」

---

## 0. 一句话定义

把现有「问AI（整段 + 纯文本）」扩成**「帧级 / 时段级 + 图 + 存档事实」**：暂停 → 右上角出按钮 → 抓当前帧（或 A–B 区间均匀 N 帧）→ 烧录时间码/帧号/版本角标 → 拼进 brief → 用户一键复制、粘给任意 Agent（带 MCP）定位该版本并给最终提示词。

---

## 1. 目标 / 非目标

### 目标

1. 暂停状态下，画面右上角出现「问AI」，点击后 1 次交互拿到**可直接粘给 Agent 的完整证据包**（图 + 文本）。
2. 证据包里必须包含**这一版实际用的** prompt / params / guide(sha) / refs，以及**该版本 id**，而不是面板当前值。
3. 支持在暂停态用 A–B 标选**问题区间**，按区间均匀取 N 帧（默认 6），用于判断「何时开始出错」（杯子是第 3 帧才凭空出现的）。
4. 复用现有抽帧能力，不新增抽帧实现；不新增后端/插件/云端依赖。

### 非目标（本版明确不做）

- 网页内调 LLM / 内置 VLM；网页不做「这片子是废片」的判定。
- 一键按 AI 建议自动重写提示词并自动重跑（绕过用户确认、费用不可控）。
- 整段单张大拼图当主证据（只在总览用一格）。
- 全片自动扫描审核（二期，见 §11）。
- 改 ComfyUI 插件、重启云端实例。

## 2. 用户流程（三个入口，同一面板）

| # | 场景 | 操作 | 结果 |
| --- | --- | --- | --- |
| F1 单帧快速诊断 | 分镜预览/导演台单段播放 → 播到可疑处点暂停 | 右上角「问AI」→ 面板直接出当前帧 | 复制 brief（1 帧）粘给 Agent |
| F2 区间诊断 | 暂停后想确认「从哪一秒开始出错」 | 面板里点「选区间」→ 在区间条上点起点、点终点 | 自动取 6 帧，每帧角标不同，附 2×3 总览 |
| F3 版本对比 | 已经重跑过一版，怀疑新版更差 | 面板顶部「版本」下拉选 v2 / v3 | 取该版本视频的帧（同 shot 内切 version） |

> F3 需要播放器加载对应版本；若该版本视频不在本地缓存，只允许「选当前已加载版本」，其余置灰并提示。

## 3. 类型契约（先写类型，再写实现）

新增 `src/features/canvas-nodes/storyboard/frame-review.ts`（**纯函数，全部可单测**）：

```ts
/** 一次帧级问AI 的上下文（宿主提供，舞台只透传） */
export interface FrameReviewContext {
  projectId: string;
  shotId: string;
  shotNumber: number;
  /** 播放器当前真正加载的版本（不是 shot.cache.selectedVersionId 猜的） */
  versionId?: string;
  /** 版本序号（1 基）与总版本数，用于「v3 / 共 4 版」 */
  versionIndex?: number;
  versionTotal?: number;
  /** 段号文案，如「段2」 */
  segmentLabel?: string;
}

/** 舞台在暂停时报给宿主的事实 */
export interface PausedFrameInfo {
  /** 源内时间（秒），已含 trimStart 折算 */
  timeSec: number;
  durationSec: number;
  /** 是否停在片尾（ended） */
  atEnd: boolean;
}

/** 区间（秒，源内时间） */
export interface FrameRange { startSec: number; endSec: number }

/** 取帧计划 */
export function planFrameTimes(range: FrameRange | null, count: number, durationSec: number): number[];
/** 角标文案：`段2 · v3 · 00:00:03.416 · f82` */
export function frameLabelText(ctx: FrameReviewContext, timeSec: number): string;
/** 帧号：round(t × 24)（节点内部 DIRECTOR_FPS=24） */
export function frameIndex(timeSec: number): number;
/** 截图落盘相对路径（相对数据根） */
export function frameRelPath(projectId: string, shotId: string, versionId: string, timeSec: number): string;
/** brief 的「定格证据」段落（追加在现有 shot-ai-brief 末尾） */
export function buildFrameEvidence(input: {
  ctx: FrameReviewContext;
  paused: PausedFrameInfo;
  range: FrameRange | null;
  frames: Array<{ timeSec: number; absPath: string }>;
  /** 该版本存档事实（见 §7），缺省则整段省略 */
  archived?: ArchivedFacts;
  /** 用户填的症状描述 */
  symptom?: string;
}): string;
```

`ArchivedFacts` 取自 `WorkbenchShotVersion`（已存在字段，无需改数据结构）：

```ts

  guide?: { id: string; frames?: number; sha256?: string } | null;
  refs: Array<{ slotNo: number; kind?: string; title?: string; note?: string }>;
  createdAt?: string;
  versionTotal?: number;
}
```

## 5. 取帧与落盘规格

### 5.1 取帧

- 复用 `src/shared/utils/video-frame.ts::extractVideoFrame(url, t)`（已存在：seek + 300ms 兜底 + JPEG 0.92）。
- 单帧：`t = paused.timeSec`。
- 区间：`planFrameTimes(range, N, duration)`，**含两端**：`t_i = A + (B - A) * i / (N - 1)`（N≥2；N=1 退化为 A）。
  - 例：A=2.90、B=4.10、N=6 → 2.90 / 3.14 / 3.38 / 3.62 / 3.86 / 4.10。
  - **N 按时长自适应**（2026-11-20 调研后修订，原为固定 6）：

    | 区间时长 | 默认 N | 平均间隔 |
    | --- | --- | --- |
    | ≤ 2s | 4 | ≤0.67s |
    | 2–5s | 6 | 0.33–0.83s |
    | > 5s | 8 | >0.71s |

  - 用户仍可手动切 3 / 6 / 9；`planFrameTimes` 只认传入的 N，不自作主张。
- 每帧：长边压到 **1024**（等比），JPEG **0.82**。6 帧总量目标 **≤ 900KB**。
- 总览拼图：2×3（9 帧时 3×3），每格下方留 14px 黑条写角标，整体长边 ≤ 1024，JPEG 0.8。**仅作总览，不作主证据**。
- 抽帧失败（CORS 污染画布 / 源不可解码）：该帧记 `missing`，不阻断整批；全部失败则面板只给文本 brief + 提示「本段视频不允许抽帧，请用系统截图」。

### 5.2 落盘（不进 CAS、不进资产库）

- 相对路径：`projects/<projectId>/media/frames/<shotId>/<versionId>/t<秒3位>.jpg`
  - 例：`projects/YqzOHlpnmUzr/media/frames/shot-1712.../v-abc123/t03.416.jpg`
- 写盘：直接 `writeFileBlob(relPath, bytes, 'image/jpeg')`（`src/platform/fs.ts`），**不走 `putMedia`**（CAS 是内容寻址资产库，审片帧是临时证据，混进去会污染「孤儿回收/去重」口径）。
- 清理：同目录超过 200 个文件或超过 30 天 → 打开面板时顺手删最旧的（`listDir` + `removeFile`），上限写常量，不动用户其它目录。

## 6. 口径细节（最容易出错的三处）

### 6.1 版本必须取「真正在播的那一版」

- 现状：`shot.cache.selectedVersionId` 是**选中**版本；用户可能在历史抽屉里点到老版本播放，此时选中值 ≠ 正在播的。
- 规则：`context.versionId` 从 `activeMediaStorageKey` 反查 `shot.cache.versions[].storageKey` 命中项；查不到则 `versionId = undefined`，brief 里写「版本未知（当前播放媒体无对应版本记录）」，**不猜**。

### 6.2 存档 prompt ≠ 面板 prompt

- 「杯子凭空掉下来」这类问题，多半是**生成时那一版**的词/图/引导有问题，而不是用户现在面板里刚改的新词。
- brief 规则：`archived.prompt` 有值且与面板当前 prompt 不同 → **两段都出**，明确标注「生成时用的（存档）」/「你当前面板里的（未生效）」；只在相同时省略第二段。

### 6.3 引导帧映射只能近似

- 节点内部 `DIRECTOR_FPS = 24`（`director-pack-builder.ts` / `director-plugin-payload.ts`），帧号 = `round(t × 24)`。
- `guide_frames` 是**段数**（示例 22），不是帧号；brief 里只给「近似第 N 帧」并显式标注 `（近似，guide 为 22 段，与 24fps 不严格对齐）`，禁止让 AI 当精确对齐依据下结论。

## 8. 错误与降级矩阵

| 情况 | 表现 | 是否阻断 |
| --- | --- | --- |
| 本段视频跨域无 CORS，`drawImage` 污染画布 | 截图全部失败 → 只给文本 brief，面板提示「本段视频不允许抽帧，请用系统截图后手动附上」 | 否 |
| 抽帧个别失败 | 缺帧在列表里标 `(取帧失败)`，其余照给 | 否 |
| 当前播放媒体查不到 version 记录 | brief 写「版本未知」 | 否 |
| 版本视频未本地缓存（F3 切版本） | 该版本选项置灰 + 「该版本未在本地缓存」 | 是（仅该版本） |
| 剪贴板无权限 / 非 https | 复制失败 → 弹出可全选文本的只读框 + 提示手动复制 | 否 |
| `volume` 为 0 / 视频未 loadedmetadata | 不渲染问AI（`duration` 无效时取帧必然失败） | 是（不显入口） |

- [ ] 插件目录 `git status` 干净、云端任务未中断（本轮不碰插件/云端）。

## 12. 社区 / 开源调研结论（2026-11-20，先查再定）

> 结论先行：**我们要做的这件事在开源世界里没有现成的「暂停→截图→问AI」同款 UI，但它的两个关键算法决定都已被验证过，而且验证结果正好否掉了「一张大拼图」和「全片扫帧」两种做法。**

### 12.1 直接同构的参考

| 项目 | 它做了什么 | 对我们的意义 |
| --- | --- | --- |
| **VGCap**（`arXiv 2610.21758`，代码 `github.com/lolo123-123/VGCap`） | 面向 AI 生成视频的质量评估：用**多帧视觉证据**「最小修订」源提示词得到全局描述，再配**不依赖提示词的分段描述**，评估空间质量/时序质量/文视对齐 | 与我们「改提示词前先看多帧」内核一致；其分段策略（<16 帧 1 段、16–23 帧 2 段、24–31 帧 3 段、≥32 帧 4 段）可直接借来做二期抽样 |
| **vidqa**（`github.com/DSmereski/vidqa`，`pip install vidqa-cli`） | 本地确定性视频 QA CLI + MCP，28 条命令；`timing` 查重复帧/冻帧/卡顿 p50-p99，`scenes` 查切点，`when "某文字"` 返回出现区间，`moments` 自动切章节；每次输出 ≤4KB 紧凑 JSON + 唯一 exit code；本地 VLM 只作最后可选一层 | **二期方案的骨架**：先用确定性指标把「可疑秒数」算出来，再只把这几个窗口交给 VLM。设计契约值得照抄：便宜的先跑（deterministic → OCR → VLM） |
| **LTX-2 Retake**（`/v1/retake`，`start_time`+`duration`，最少 2s，输入≥73 帧） | 只重生成指定时间窗，窗口外原样保留 | **能力边界必须写清**：H3 没有 retake，我们的「选时段」只能取证 + 改词重跑整段，不能承诺「只重画这几秒」 |
| **ComfyUI-IF_VideoPrompts**（`if-ai`） | 把 Qwen2.5-VL 接进 ComfyUI，对视频/帧序列出描述与负面提示词 | 证明「VLM 审片回灌提示词」可行；但它是**插件内**实现，我们按已定纪律走外置 Agent，不往插件里塞 |
| **ComfyUI-QwenVL**（`1038lab`） | 视频帧序列输入 + 按 ctx 自动缩放每帧 token 预算，防 context 溢出/CUDA OOM | 帧数/分辨率/token 预算的经验来源（我们单帧长边 1024、6 帧 ≤900KB 的取值与之同量级） |
| **Code2Video / armory PR#54** | agentic 修复循环里 VLM critique 是「**1 call with M image blocks**」 | 印证：一次给多图 + 单次调用，不要多轮来回 |
| **VBench**（`Vchitect/VBench`，CVPR2024） | 16 个评估维度：`temporal_flickering`（静态帧 MAD）、`subject_consistency`（DINO 跨帧相似）、`background_consistency`（CLIP）、`motion_smoothness`、`dynamic_degree`(RAFT) | 「杯子凭空出现」这类问题里，**物体出现/消失 + 光流突变**是可确定性度量的；不必全靠 VLM。VBench 依赖重，不装产品，只借指标定义 |
| **TailCam / Label Studio 主动学习** | 模型只把「不确定的帧」送人工复核 | 二期 UI 口径：AI 出清单，人只审可疑项，别让人从头看到尾 |

### 12.2 被调研否掉的两种做法

1. **「N 帧拼一张大宫格喂 LLM」**——VGCap 走的是「分段描述」而不是拼图，IF_VideoPrompts/QwenVL 也是按帧序列喂；拼图会把小物件压到几十像素，「杯子」这种目标直接消失。**定稿：每帧独立原图 + 拼图只做总览。**
2. **「全片每段抽 3 帧 = 180 图交给 VLM」**——vidqa 的整套设计就是反对这个：确定性指标几乎零成本且可复跑，VLM 只该用在少量疑难窗口。**定稿：二期先算指标，再挑窗口。**

### 12.3 对一期 SPEC 的修订（已回写上文）

- §5.1 帧数策略从「固定 6」改为**按时长自适应**：`≤2s → 4 帧`、`2–5s → 6 帧`、`>5s → 8 帧`，用户仍可手动选 3/6/9。理由：VGCap 按帧数分段、vidqa 的 `--every` 抽帧都是「随时长定密度」，固定 6 帧在 2 秒段上等于每 0.4 秒一帧（过密），在 10 秒段上等于每 2 秒一帧（漏事件）。
- §12.1 的能力边界要写进 brief：**「H3 无局部重绘，本段只能整段重跑」**，避免 AI 给出「只重画 3.0–4.1s」这种我们做不到的方案。

### 12.4 二期重构后的形态（待拍板）

```
① 本地确定性预筛（零 API 成本，可复跑）
   - 逐帧 pHash/SSIM 突变 → 候选「出现/消失/闪跳」时间点
   - 重复帧 & 冻帧率 → 候选「卡住/静止」区间
   - 场景切点 → 排除正常硬切，避免误报
② 只对候选窗口做区间多帧取证（复用一期能力，每窗口 4–8 帧）
③ VLM 复核 → 输出「第 N 段 3.0–4.1s：道具凭空出现，建议改 X」
④ 用户点条目 → 跳到时间码 → 走一期的问AI
```

预计单集（60 段）从 180 图降到 **8–15 张**，且①②完全离线、可重复。

### 12.5 调研里没有的东西（避免误判"抄到了"）

- 没有任何开源项目做「**暂停 → 右上角问AI → 自动带版本存档 + 时间码 + 角标烧图**」这套制片向 UI。这部分是我们自己的产品设计，需要按本 SPEC 实现，不存在可直接复用的现成代码。
- 没有适配 Minimax H3 的「局部重绘」实现；LTX 的 retake 是另一套模型与管线，不可移植。
