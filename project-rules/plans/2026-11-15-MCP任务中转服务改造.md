# MCP Task Broker：AI 任务中转服务改造

日期：2026-11-15

## 目标

所有 AI 任务的发起、排队、执行、进度、预览、结果、取消由 MCP 服务持有；网页只是客户端与编辑器。

用户刷新、关闭、换浏览器、多开，都只断开订阅，不丢任务、不丢进度、不丢预览。

## 非目标

- 不让 MCP 直接改画布 Yjs 文档；画布节点落图仍由网页在重连后应用 MCP 结果。
- 不保留网页本地任务队列作为第二事实源。

## 当前根因

1. `useDirectorRun` 在浏览器内存 / sessionStorage 持有 activeJob、jobId、进度；刷新即断。
2. 图片任务由 MCP 投递、网页执行；执行权在网页。
3. 批量视频由网页一次性提交，guide 在提交时解析；上一段未完成时取不到，重生成已完成片段也不会从片段缓存取 guide。
4. 导演台一个片段只有一份 `media`，没有版本/缓存概念，历史与片段无归属。
5. 多开页面各自执行，天然重复/互相覆盖。

## 架构

### MCP Task Broker

- 持久化目录：`.lf/zeroexo/app_meta/tasks/<taskId>.json`
- 单写者：仅 MCP 推进任务状态
- 状态机：`queued → running → success | failed | canceled`
- 任务类型：`director_run` / `canvas_image` / `subject_image`
- 任务记录：
  - `taskId / projectId / kind / createdAt / updatedAt`
  - `request`：prompt / model / size / seed / segment 列表
  - `segments[]`：shotId、guide 来源、comfyJobId、promptId、progress、result
  - `previewKey`：最后一帧 CAS key
  - `outputs[]` / `error` / `attempt`
- MCP worker：
  - 调 ComfyUI
  - 批量串行
  - 执行时解析上一段缓存 guide
  - 下载结果、写 CAS、写资产记录 / workbench
  - 重试、超时、取消、重启恢复
- 网页：
  - 提交任务
  - SSE / 轮询订阅
  - 渲染进度、最后一帧、结果
  - 重连后应用待落图结果

## 片段缓存模型

```ts
shot.cache = {
  selectedVersionId: string,
  versions: Array<{
    id: string,
    storageKey: string,
    guide?: { id: string, storageKey?: string, frames: number },
    prompt: string,
    params: Record<string, unknown>,
    sourceVersionId?: string,
    createdAt: string,
    status: 'done' | 'failed' | 'archived'
  }>
}
```

- `shot.media` 作为 `selectedVersion` 投影，兼容播放。
- 重生成第 N 段固定取时间线上一段当前选中版本的 guide。
- 上一段无选中版本或无 guide：明确本段无引导输入，禁止回退 `LAST_GUIDE`。
- 片段移出轨道：历史保留并归档，不与新建同名片段自动关联。
- 归档历史需要用户手动「发送引导到插槽」。

## 资产抽屉

新增一级「导演台」，按片段组织：

- 片段槽显示当前缓存缩略图，类似主体封面。
- 点击轨道片段卡 → 打开资产抽屉并定位该片段历史。
- 历史项操作：设为片段缓存、查看提示词、发送到画布、删除此版本。
- 归档片段显示「轨道中已移除」。

## 实施阶段

1. MCP Task Broker 存储、状态机、提交/查询/取消/订阅 API、任务中心 UI。
2. 图片任务迁移：画布图片、主体图片由 MCP 执行，网页只订阅并应用。
3. 导演台视频迁移：MCP 串行推进、执行时取 guide、持久化预览帧。
4. 片段缓存与导演台历史抽屉。
5. 清理网页本地队列、sessionStorage 续接、网页直连 ComfyUI 生成入口。
6. 数据迁移：旧 `media` → cache v1；旧历史保留；归档不自动关联。

## 验收

1. 15 段批量，刷新 / 关闭 / 换浏览器 / 多开：
   - 任务列表、进度、最后一帧预览、结果都在
   - 不重复提交
2. 已生成 1/2/3，刷新后只重生成第 2 段：
   - 请求明确带第 1 段当前缓存 guide
   - 输出连续
3. 切换第 2 段缓存版本后，第 3 段重生成使用新 guide。
4. 删除片段：
   - 历史保留并归档
   - 标记「轨道中已移除」
   - 新建同名片段不自动继承
5. 多开：
   - 同一 taskId 只有一个执行者
   - 所有页面同一进度
   - 取消同步

## 已确认决策

- 片段历史保留全部版本。
- 移出轨道的片段进入归档历史，不再与新建同名片段自动关联。
- 归档历史要重新用于引导，必须用户手动发送到插槽。
- 2026-11-15 追加：**ComfyUI 插件只做被动执行器，不持有任何项目数据**（不读写 projects/*、不维护跨作业 LAST_GUIDE）。
- 2026-11-15 追加：**一个任务 = 一个批次**。批次带全部选中段的提示词/参数 + 每段 guide 指令（initial/chain/none）；
  插件内部串行、段间自链，每段完成即回传 video+guide（用于立即展示，不是触发下一段的信号），MCP 不在关键路径上。
- 2026-11-15 追加：**分段选择合法**（如 3,4 + 6,7）。每个连续块只解析起始段的「上一段当前缓存 guide」；
  块内由批次 chain 续接，不逐段发送 guide；起始段没有 guide 时按 none 生成（首次生成第一段本来就没有，不拒绝）。
- 2026-11-15 追加：引导插槽是**上一段当前缓存版本的只读投影**，不重复落盘到下一段 shot.guide；
  手动引导才写 shot.guide。引导图标即开关：关闭=不用引导；放入手动引导数据强制打开。
- 2026-11-15 追加：片段 = 版本集合，**最新版本默认启用（封面）**，用户可手动启用旧版本；
  从历史把视频设为片段封面时，下一段的引导引用立即跟着更新。
- 2026-11-15 追加：每段有自己的预览键，批量生成按段落盘；刷新后每段显示自己的预览，不把整批压到一段。
- 2026-11-15 追加：首段也支持引导（历史/上一部末尾 guide 作为起始延续），只是没有「上一段自动跟随」。

  MCP 提交一个批次（`reference_video_batch`），逐段轮询状态、逐段落 CAS/资产记录/片段缓存/历史。
- 插件：新增连续段批次（initial/chain/none），批次内部串行自链、每段完成即回传；
  删除 `LAST_GUIDE` / `use_prev_guide` / prevJobId 兜底，插件不持有项目数据。
- 片段缓存：`shot.cache` 版本模型 + media 投影；片段历史弹层（切缓存/看提示词/删版本）；
  历史视频「设为片段封面」→ 选中该版本并联动下一段引导引用。
- 每段预览：任务段级 previewKey 落盘，前端按段显示；任务中心显示最新一帧。
- 画布图片任务由 MCP 执行，网页只订阅并幂等落成画布节点。

## 本地 E2E 实测（2026-11-15）

环境：本机 ComfyUI（RTX 5060 Ti 8G，低显存链）+ 临时数据根 + MCP fs-server/broker + 新插件批次。

- 任务：导演台选 s2、s3，s1 当前缓存 guide=gd_a473b0a03846。
  - task 段 1（s2）guide=gd_a473b0a03846 / source=cache / sourceShotId=s1；
  - 段 2（s3）guide source=chain / sourceShotId=s2；
  - 两段均 success，各自 previewKey 落盘（s2 的 preview-1、s3 的 preview-3，互不覆盖）；
  - 视频进 CAS、资产记录 originNodeId=s2/s3 且带各自 guide、workbench `shot.cache` 追加版本并选中、
    `media` 投影、`firstFrameKey` 指向本段预览；`media/guides/<gd>.safetensors` 落到本地；
    任务只在两段都成功后才 success。
- 切换 s1 的 selectedVersionId 后重提交 s2：task 段 guide 立刻变成新版本的 gd_108764cab518。
- 发现并修复：插件 `GET /jobs/{id}` 对批次父 job 调用 refresh_job，导致「第一个子段成功」被误判成整批 success；
  现在批次只由 worker 维护段状态，父 job 不再 refresh。
- 发现并修复：预览文件原先按任务只留最新一张，导致前一段 previewKey 指向已删除文件；现在按段保留。
- 历史抽屉导演台类目改为按片段分组（一个片段 = 一个集合，版本在抽屉内瀑布流、默认最新为封面）；
  旧资产没有 originNodeId 时按标题 `seg-xxx` / `片段 N` 回退归组。
- 收尾（2026-11-15）：
  - 抽屉内片段版本改回**瀑布流**，不再横向挤压；片段集合第一级 + 面包屑「全部片段 / 镜头 N」。
  - 任务队列从右下角浮层移进抽屉，独立「任务」分组，运行中/排队中可取消；删除 `TaskQueueDock`。
  - 片段封面改用**成品视频最后一帧**（插件 `_extract_last_frame` → MCP 导入项目）；WS 低清帧只作生成中预览。
  - 修复重跑已完成片段时 `comfyRun` 被 `allDone` 重置、卡片永远显示「完成」的问题；
    运行中优先显示排队/生成中，旧视频不再顶替实时预览。
  - 修复 `seed=-1` 被 ComfyUI 校验拒绝：插件把负 seed 归一化为随机正整数。
  - 修复删除素材记录 release CAS 导致画布节点/导演台/主体引用失效：`removeAssets` 现在只删元数据。
  - MCP 原子写增加 Windows `EPERM/EBUSY` 重试，避免瞬时占用把任务判失败。
  - MCP `server-info` 版本改为读 package.json，不再写死 0.2.0。
