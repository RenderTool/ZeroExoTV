# C-30 副本 = 完整副本（画布历史 / 分镜历史 / 判定 随副本一起复制）

状态：待用户确认（不推送，本地自测）

## 一、现状（已核实，不是猜测）

1. 「创建副本」的实现是 `src/features/sub-canvas/canvas-copy.ts:121` → `createCanvas()`。
   写盘内容只有 `nodes / edges / viewport / metadata`，落到 `projects/<pid>/canvases/<cid>.json`。
   **历史一条都不带过去。**

2. 历史资产挂在**项目层**，不在画布层：
   - 索引文件：`.lf/zeroexo/app_state/zeroexo%3Aassets.json`
   - 每条记录只有 `projectId`（外加 `data.origin='generation'`、`data.originSource='canvas'|'director'`、审核判定等）
   - 历史过滤只按 `projectId`：`src/features/canvas-assets/history-utils.ts:92 filterHistoryAssets`、`:124 countHistoryBySourceAndKind`
   - 判定/采纳等审核信息挂在资产记录的 `review` 上，同样跟 `projectId`

3. 结果：副本里打开「历史」，看到的不是副本自己的历史。
   现状口径下没有"副本历史"这个概念——历史永远属于整个项目，所以副本既拿不到独立的一份，也不会因为创建副本而丢东西。

## 二、目标口径（副本 = 整个项目的一份版本）

用户 2026-11-22 定调：**副本 = 把当前整个项目的全部历史数据创建成一个版本**，不是"某块画布的历史"。

所以副本是**项目级版本快照**，一个副本 = 项目在创建那一刻的完整数据版本：

- 画布：全部画布文档（主画布 + 已有副本）的图快照
- 画布历史：所有生成产物记录（图片/视频/音频/文本）
- 分镜历史：导演台全部片段产物、版本集合、封面
- 判定：每条记录的采纳 / 打回 / 待审
- 引导：每个片段引用的 `gd_*.safetensors`（共享文件，只带引用）
- 实体：剧本 / 主体树 / 导演台当前状态

进入副本 = 进入这个版本；后续在副本里生成的新产物只追加到该版本，主版本不受影响。
媒体（CAS）文件全局共享，**创建副本只复制数据层，不复制任何媒体文件**（磁盘零增量）。

## 二之二、数据模型

副本目录（新增，与现有 `canvases/<cid>.json` 并存）：

```
projects/<pid>/versions/<vid>/
  manifest.json          # 版本元信息：来源版本、创建时间、统计
  canvases/              # 全部画布文档快照（含主画布与其它副本）
  assets.json            # 该版本的历史记录切片（含判定、originSource）
  entities/{script,storyboard,workbench}.json
  guides.json            # 引用的 guide id → sha256 / bytes
```

- 版本 id `vid` 与副本画布 `cid` 绑定（1:1），副本页签打开时读该版本，而不是读项目当前数据。
- 只读语义：版本目录内容不随项目当前数据漂移；在副本里继续生成时，**写的是该版本的 `assets.json` 与画布快照**，不回写项目当前。
- 删除副本 = 删该版本目录 + 副本画布 JSON，**不删 CAS、不删引导文件、不动主版本**。

## 二之三、与现有实现的差异（要改的）

| 现状 | 改成 |
|---|---|
| `createCanvas()` 只写 graph | 创建副本时额外写 `versions/<vid>/` 全量数据层快照 |
| 历史资产只有 `projectId` | 资产记录加 `canvasId`/`versionId`，历史过滤带版本维度 |
| 副本页签历史 = 项目当前历史（混） | 副本页签历史 = 该版本切片（只读） |
| 导出只带当前项目历史 | 导出带版本目录 + 引导 + 快照，导入完整还原 |


## 三、实现方案

### 1. 资产记录加画布维度

- `Asset` 增加 `canvasId: string`（生成时用 `getCurrentCanvasDocId()`，主画布为 `main`，副本为 `<cid>`）。
  写入点：`src/features/canvas-assets/history-autoland.ts`（生成产物落库唯一入口）。
- 取值必须显式传，禁止在落库层再读全局（`data.canvasId` 目前只有剧本在用，语义要统一）。

### 2. 历史过滤改为 (projectId, canvasId)

- `filterHistoryAssets` / `countHistoryBySourceAndKind` / `countHistoryByCategory` 增加 `canvasId` 参数。
- 主画布（`main`）显示 `canvasId='main'`；副本显示自己的 `cid`。
- 老数据没有 `canvasId`：按 `main` 兼容（只读判断，不改盘上数据）。

### 3. 创建副本时克隆索引

新增 `cloneCanvasHistory(projectId, sourceCanvasId, targetCanvasId)`：

- 读项目资产索引，筛 `projectId` + `canvasId===sourceCanvasId` + `origin='generation'`
- 逐条生成新 id（`crypto.randomUUID` 同风格），保留 `storageKey / cas.hash / kind / title / createdAt / originSource / review`
- 一次批量写入索引（**不是逐条 addAsset**，避免 N 次重写 226KB 索引）
- 不复制 CAS 文件、不复制缩略图（靠 storageKey 复用）

调用点：`canvas-copy.ts` 在 `createCanvas` 成功后调用；失败只 warn，不阻断副本创建（但要在 UI 提示"历史复制失败"）。

### 4. 分镜（导演台）历史

导演台是项目级单份 `entities/workbench.json`，副本没有自己的导演台。两个口径二选一：

- A（推荐）：副本的「分镜历史」= 创建副本那一刻 workbench 的产物快照，克隆索引记录到副本 `canvasId`，副本内只读展示，不回写 workbench。
- B：副本共享项目级导演台历史（标注"项目导演台"，不区分副本）。

选 A 才能满足"副本 = 完整副本"；B 会让副本和主画布继续混。

### 5. 删除副本时的处理（红线）

- 删除副本：**只删该 `canvasId` 的索引记录**，绝不删 CAS 文件、绝不自动回收媒体。
- 与既有红线一致：任何"自动删除 CAS / 历史文件"的逻辑都不恢复（`purgeOrphanMedia` 已停用）。

### 6. 不动的部分

- 「拷贝项目」(`duplicateProjectAssets`) 已会复制资产记录，保持不变。
- 本次不推送，本地自测。

## 四、验收

1. 主画布生成 3 图 + 导演台 1 段 → 创建副本 → 副本历史里同样 3 图 + 1 段，判定一致。
2. 主画布历史条数不变；副本再生成 1 图，只出现在副本历史。
3. 索引文件体积增量只与记录条数相关（无媒体复制）；CAS 目录文件数不变。
4. 删除副本后，主画布历史完好，CAS 文件一个不少。
5. 老项目（无 `canvasId` 字段）打开后历史显示与现在一致（全部归主画布）。

## 四之二、导出项目必须包含「全部历史 + 引导数据」（用户 2026-11-22 追加）

### 现状（已核实）

`src/pages/home/services/export-projects.ts`（v2）导出内容：

- 主画布 graph、剧本 `script.json`、主体 `subjects.json`、导演台 `workbench.json`
- 本项目资产记录 `assets/<pid>/assets.json`（历史记录 + 判定在里面）
- 副本画布 JSON + 所有 `storageKey` 指向的二进制（`files/`）

**漏掉的**：

1. **引导数据全部丢失**：`src/pages/home/services/project-documents.ts:15` 的
   `STORAGE_KEY_PREFIX = /^(image|video|audio|cas):/` 不认 `guide:` 前缀，
   `blobForStorageKey()` 也不认 → `media/guides/gd_*.safetensors` 一个都不会进 ZIP。
   后果：换机导入后，片段里"含引导"只剩一个取不到的 id，续拍直接断。
2. **画布磁盘历史快照没导**：`projects/<pid>/canvases/history/*.json`。
3. **实体快照没导**：`projects/<pid>/entities/snapshots/{storyboard,workbench,script}/*.json`
   （目前只在导出前做一次 hash 校验并 log，不打包）。

### 要做的

1. `collectStorageKeys` 增加 `guide:`；`blobForStorageKey` 走 `readCachedGuideBlob()` 读 `media/guides`。
2. ZIP 内固定路径：`guides/<projectId>/<gd_id>.safetensors`，并在 `projects.json` 增加
   `documents.guides: string[]`（导入按清单还原，不靠目录扫）。
3. 导出 `canvases/history/<pid>/*.json` → ZIP `canvas-history/<projectId>/`，
   实体快照 → `snapshots/<projectId>/entities/{storyboard,workbench,script}/`。
4. 导入（`import-projects.ts`）补齐三件事：
   - 引导写回 `media/guides/` 并 `recordGuideSha()` 重建 `app_meta/guide-sha.json`
   - 画布历史快照写回 `canvases/history/`
   - 实体快照写回 `entities/snapshots/`
5. 导入必须是**只加不删**：任何情况下不得清理目标项目已有的引导/历史文件（用户红线）。

### 验收

1. 导出 A 项目 → 删本地 → 导入 → 历史图片/视频全在、判定全在、每段引导都能继续续拍。
2. ZIP 内 `guides/<pid>/` 文件数 = workbench 里引用到的 guide id 去重数。
3. 导入后 `app_meta/guide-sha.json` 与引导文件一致（sha 校验通过，不触发重下）。
4. 再导入第二遍：不重复写、不覆盖已有更新版本、不删任何文件。
