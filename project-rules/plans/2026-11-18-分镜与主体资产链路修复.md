## 0. 背景

用户在导演台与 MCP 实测中连续报出以下问题，全部按 “可复现现象 + 根因 + 验收动作” 落条目，不写模糊描述：



1. 连播没有把所有片段的**封面**按顺序连续播放一次。

2. 简单道具被生成三视图 / 细节拼版。

3. 提示词仍在描述角色外貌（脸 / 发型 / 身材 / 服装）。

4. 场景没有复用已有概念分镜，仍强制重新出轴图。

5. 概念图与最终视频场景完全不一致。

6. 删除主体后，分镜 / 提示词里的引用没有失效提示；补回后不恢复。

7. 目录未授权时不弹授权框，反而输出大段文本让用户自己找。

8. 已显示授权成功，页面仍反复要求授权；同一目录无法再次授权。

9. 分镜 “提示词 + 空素材” 没有修好。

10. 安装说明写 “把下面这段复制给 Agent”，误导成复制授权 MCP 路径。

11. 分镜 @ 弹层第一栏不是主体，且不定位当前插槽已选主体。

12. 分镜引用了未转主体前的人设图，同一张图占用两个插槽。

13. 点主体封面时插入 `@主体名`，而不是 `@主体名·基础状态（封面）`。

14. 主体锚定重复写两次。

15. 出现 “凡正文出现其中任一主体，即按该图锁形制、不锁构图” 这类空话。

16. 视频提示词没有说清 “模型需要什么输入、锁什么、不锁什么”。

17. skill 是 TS 硬编码长文本，不是 `SKILL.md` 规范。

18. 本地服务（8787/8790）在 Agent 干活期间反复掉线。

## 1. 口径（硬性，逐条可验收）

### 1.1 提示词



* **任何提示词不得描述角色外貌**：不写脸、发型、身材、服装的具体描写；场景 / 道具提示词同样禁止。

* 主体只在定义行锚定一次；**禁止**再追加一行「主体锚定：…」重复映射。

* **禁止**输出「凡正文出现其中任一主体，即按该图锁形制、不锁构图」这类汇总句；它对视频模型没有约束力，只消耗 token。

* 道具 / 简单资产：**形态由道具自身复杂度决定**，不统一。简单道具走白底单视图（单品居中，禁止多格、同款第二件）；

  结构复杂、需要交代多部件 / 工艺 / 边缘 / 接口的道具才出「整体 + 1 个细节特写」或按需三视图。默认单视图，加形态必须由复杂度或用户显式指定。

* 场景：单张概念图；**已有分镜概念帧可直接复用**，不强制重新生成轴图。

* 分镜空素材（无参考图）：必须能生成；提示词不得引用不存在的 `@PictureN`。

### 1.6 生成链路完整性（2026-11-18 串台事故后加，硬性）



* **提交提示词唯一来源是分镜结构化提示词&#x20;**`imagePrompt`：`imagePrompt` 为空时**禁止**静默回落 `videoPrompt` / `description`，

  也禁止拼 `第 N 段` 占位；一律按「本段没有分镜结构化提示词」拒绝运行并给出可读原因。

* **提示词里的每个&#x20;**`@引用`**&#x20;必须解析到可用槽位**：主体 / 图片被删导致槽位失效时拒绝运行（`mention-unresolved`），

  不允许「正文写了 3 个主体、槽位只剩 1 张图」照样提交。

* **片段封面只认本片段自己生成的产物**（`originNodeId === shot.id`）；跨来源采用必须显式操作并保留来源标记，禁止静默认领。

* **引导槽预览只接受&#x20;**`cas:`**&#x20;键**：ComfyUI 8188 的 `previewKey` / `firstFrameKey`（`http://127.0.0.1:8188/view?...`）不得当 `storageKey` 传，

  否则引导槽永远显示「视频不可用」；预览回落到上一段成片 `media.storageKey`。

### 1.2 素材与绑定



* 视频生成必须把概念图 / 分镜帧作为**真实输入素材**提交，并在提示词里用 `@PictureN` 精确绑定；禁止只写文字描述。

* 概念图与成片不一致，固定按三条排查：① 素材是否真的进了 payload；② `storageKey` 是否指向该素材；③ 提示词是否绑定到该素材编号。

* 分镜取主体素材**只能取主体库里的图**，不得用未转主体前的人设图冒充主体；同一张图不得占两个插槽。

### 1.3 主体与「基础状态 = 封面」



* **主体只是根节点，本身不代表任何图片**：主体行没有图、不能当素材用。图片只属于「状态图」。

* **录入资产默认落「基础状态」，且默认基础状态 = 封面**：用户不显式切换封面时，封面恒等于基础状态首图；

  **禁止出现「基础状态为空、主体封面却有图」**（除非用户手动把某张图设为封面）。

* **任何能 @ 主体的列表（分镜提示词、资产抽屉、@ 弹层、录资产、槽位选择器）点主体 = 展开状态列表**，不是选中封面；

  只有点具体状态图才写入引用。点主体直接传封面属违规实现，一律删掉。

* 写入的引用必须带状态：`@主体名·基础状态（封面）`（基础状态）/ `@主体名·XXX状态`；**禁止**只写 `@主体名`。

* 分镜 @ 弹层第一栏是「主体」，并定位到当前插槽已选主体；该主体有多个状态时直接列状态供切换。

* 删除主体后，所有引用该主体的插槽显示「失效」；补回主体后自动恢复，不得静默消失。

* 存量裸 `subject:<id>` 引用按「基础状态封面」解析（兼容读取），但任何新写入不得产生裸主体引用。

### 1.4 授权与服务



* 目录未授权：**直接弹授权框**，不输出「请自己找目录 / 复制命令」的长文本。

* 已授权成功不得再次要求授权；同一目录不得要求重新选择。

* 本地 fs-server / MCP 必须独立守护：dev/preview 关闭不得 kill 已有实例。

### 1.5 Skill



* Skill 源改为 `SKILL.md`（frontmatter：`name` / `description` / 何时使用）+ `references/`；构建时内联，运行时不依赖安装路径。

* **先给利弊再改**，禁止直接重写。
