# 分镜采样预览对齐 KJNodes Model Preview Override

日期：2026-11-16
范围：**只改本地 ComfyUI 插件 + 本地网页**，不动线上环境。
目标：生成视频时，用户能在右侧实时看到**整段视频的采样渲染过程**，刷新网页不丢；不是单帧占位，也不是前端自造的定时器轮播。

## 背景 / 结论

当前插件自研的 `minimax_director_preview` 预览链路存在三个结构性问题：

1. 采样回调里同步解码/编码多帧，直接阻塞采样线程；48 帧 × 1024 时任务在 1/8 被取消。
2. 前端把预览当成“一张图”或“48 张 JPEG 数组 + 定时器”，不是 ComfyUI/KJNodes 的事件驱动预览。
3. 预览只走 WebSocket，刷新网页后没有可恢复的任务级预览状态。

KJNodes 的 `Model Preview Override` 已经解决同类问题，正确做法是：

- `_PreviewOverrideWrapper` 挂到 model 的 `OUTER_SAMPLE`；
- 采样线程取 latent 帧；
- `_AsyncPreviewEncoder` 在独立线程编码（有界队列，满则丢帧，绝不阻塞采样）；
- 通过 `kj_preview_override` 事件发送 `{image, mime, w, h, step, total, fps}`；
- 优先 MP4（浏览器 `<video>`），失败回退 animated WebP（`<img>`）；
- 前端按事件里的 mime 选择 video/img，并持有最近一帧/一段。

参考源码：
`D:\ComfyUI\ComfyUI_windows_portable\ComfyUI\custom_nodes\ComfyUI-KJNodes\nodes\preview_override_node.py`

## 职责边界

| 层 | 负责 | 不负责 |
|---|---|---|
| ComfyUI 插件 | 采样步预览解码、异步编码、事件发送、最近预览落盘、任务段 previewPath | 不写项目数据/CAS/资产 |
| 网页 | 订阅预览事件、video/img 渲染、刷新后从任务恢复最近预览 | 不做采样、不在浏览器里编码 48 帧 |
| 项目落库 | 段完成后 CAS/资产/shot.cache/media | 预览不是成片，不落项目资产 |

## 插件侧设计

### 1. 预览事件

沿用 KJ 的事件形状，新增插件事件（或完全复用 `kj_preview_override`）：

```
{
  "type": "minimax_director_preview",
  "data": {
    "node_id": "...",
    "segment_index": 1,
    "image": "<base64>",
    "mime": "video/mp4" | "image/webp" | "image/jpeg",
    "w": 480,
    "h": 270,
    "step": 2,
    "total": 8,
    "fps": 8
  }
}
```

不再发送 `frames: string[]` 给前端逐帧定时器。

### 2. 异步编码器

新增 `engine/preview_encoder.py`：

- `PreviewEncoder` 线程 + `queue.Queue(maxsize=2)`
- `submit(fn)`：队列满直接丢弃，不阻塞采样
- `shutdown()`：采样结束/任务结束 drain
- 编码函数只接收 CPU 侧 PIL 帧或 uint8 数组，不在采样线程做 JPEG/WebP/MP4 编码

### 3. 采样预览

`executor_core._report_step_preview` 改为：

1. 采样线程只做 TAE 解码，得到 `frames`（最多 `preview_frames`，默认 48；长边 480）；
2. 把 `frames` 交给 `PreviewEncoder`；
3. 编码线程：
   - 优先 MP4（PyAV，libx264 ultrafast，fragmented MP4）；
   - MP4 不可用/失败 → animated WebP；
   - 再失败 → 单张 JPEG；
4. `PromptServer.instance.send_sync("minimax_director_preview", payload, clientId)`；
5. 最新预览帧/片段写盘：
   `<output>/zeroexo/previews/<taskId>-s<N>-live.(mp4|webp|jpg)`
   写回任务段 `previewPath`。

参数对齐 KJ：

- `preview_frames = 48`
- `preview_fps = 8`
- `max_resolution = 480`（用户明确要求 480，避免显存/带宽卡死）
- `jpeg_quality = 80`
- `tiny_vae = taeh3.safetensors`
- `suppress_default_preview = true`

### 4. 取消/重启

- 任务结束/取消：`PreviewEncoder.shutdown()`，不残留线程
- 任务 `running` 重启：段标 `interrupted`，保留已有 `previewPath`
- 预览文件只留在插件 output，不进项目

## 网页侧设计

### 1. 事件解析

`use-plugin-director-task` 的 WS 处理：

- 删除 `frames` 定时器逻辑
- 解析 `image` + `mime`
- mime 为 `video/mp4` → 设 `preview.video = data:video/mp4;base64,...`
- mime 为 `image/webp`/`image/jpeg` → 设 `preview.image`
- 同时记录 `step/total/fps/segmentIndex`

### 2. 渲染

`StoryboardVideoStage`：

- `preview.video` 存在 → `<video autoPlay muted loop playsInline>`
- 否则 `preview.image` → `<img>`
- 不再使用 `LivePreviewFrames` 定时器

### 3. 刷新恢复

`usePluginDirectorTask.applyTask`：

- 当前段 `previewPath` 存在 → `pluginViewUrl` 转为可播放 URL
- 任务恢复时按扩展名判断 video/image
- 最近一帧/片段保留，不显示黑屏

### 4. 点击已生成片段

- 生成批次外/已完成的片段：允许点击并播放
- 只有“当前段正在重跑”时隐藏该段旧视频
- 批次内的段：锁定替换（`director-run-lock`），但允许查看

## 迁移顺序

1. 新增 `preview_encoder.py`，单测：队列满丢帧、编码失败回退、shutdown。
2. 插件改为异步编码；先用单张 JPEG 验证不阻塞采样，再开 MP4/WebP。
3. 网页解析 mime，video/img 渲染；删除定时器代码。
4. 任务 `previewPath` 恢复 + 刷新验证。
5. 48 帧/480/8fps 压力测试；确认任务不再被预览拖死。
6. 批次锁定 + 点击已完成段播放回归。

## 验收

- 生成 2 段，采样 1/8→8/8 每一步右侧画面都变化，不是固定一张。
- 每步是整段视频的 48 帧预览（MP4 或 WebP），不是 48 张 JPEG 前端轮播。
- 生成过程中点击已完成的段 1：右侧播放段 1 成片；不会被自动跟随抢回。
- 刷新网页：最近预览仍在；任务继续；完成后正常落库。
- 48 帧×480 时采样不被预览阻塞，任务不取消。
- 批次内段（2/3/5/6）锁定替换；批次外已完成段可替换/查看。
