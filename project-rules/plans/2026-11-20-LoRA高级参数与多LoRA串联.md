# C-11 LoRA 与视频主模型进「高级参数」+ 多 LoRA 串联（2026-11-20）

> 用户要求：LoRA 不能是手填文本框，要和模型一样「先拉清单再下拉选」，带推荐版本与强度；
> 视频主模型与 LoRA 都要在参数面板里放一份（高级折叠）；真实 ComfyUI 用法是多个 LoRA 串联、
> 每个各自强度，现在只有一个 LoRA，需要配套多 LoRA 节点链并接到视频模型上。

## 1. 事实（代码实证）

- 插件模板 `templates/reference_video.json` 只有**一个** `LoraLoaderModelOnly`（节点 `25`），直接吃 `UNETLoader` 的 MODEL 输出，再喂给 `ZeroExoRefVideo`。
- 参数来自 `__zx:lora_name__ / __zx:lora_strength__`，`_prepare_batch_segment` 用 `TEMPLATE_DEFAULTS` 兜底 → 面板不给值就是 8 步 turbo。
- ComfyUI 多 LoRA 机制：`LoraLoaderModelOnly` 是 MODEL 的**串联 patch**，每个节点吃上一个节点的 MODEL、按 `strength_model` 加权求和，可以任意串联；顺序影响极小（同一基座、各自强度），显存只保留一份基座 + patch。
- 云端 `/zeroexo/h3/models` 与 `/zeroexo/v1/models` 目前**只返回 unet / vae / clip**，没有 LoRA 清单 → 网页无法下拉选。

## 3. 口径

- **不自动挑 LoRA**：清单拉回来只做「推荐标签」，选哪几个、各自强度由用户决定。
- 旧插件（无 `lora` 清单 / 无链支持）时，页面明确显示「云端插件未返回 LoRA 清单，需升级插件」，不禁用但也不假装生效。
- 单 LoRA 行为与今天完全一致（仍是那一个 `LoraLoaderModelOnly`），避免回归。
- 多 LoRA 顺序按用户从上到下的顺序串联。
- 插件改动**部署需要重启云端 ComfyUI 才会生效**（本轮只落代码 + 本地构建，不重启云端）。

## 4. 验收

1. 参数面板「高级参数」可展开，视频主模型下拉与模型映射面板同一份值（改一处两处同步）。
2. 可添加 2 条以上 LoRA，每条独立强度；`params.loras` 按顺序进 payload。
3. MCP `request_director_run` 的段参数里能看到同样的 `loras`。
4. 插件 `apply_lora_chain` 单测：1 条 → 原节点；3 条 → 3 个节点串联、末端接回消费者；文件不存在 → 抛错。
5. 旧插件（0.1.2）下不报错但只用第一条（`lora_name`），页面有升级提示。
