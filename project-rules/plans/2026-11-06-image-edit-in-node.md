# C-04 图片编辑改为节点内编辑（裁剪 / 局部 / 分割）

> 需求来源：用户 2026-11-06 口述——“图片编辑在节点内实现，原本裁剪、局部、分割都在独立的弹窗中实现，
> 感觉就像一个功能被硬生生切到独立的页面去”，并给出两个候选方向要求对比。
> 本 Plan 先做**方向对比与推荐**，用户拍板后进入实现。

弹窗只是提供了一个大画布去拖裁剪框/切分网格。

## 二、两个候选方向

### 方向 1：像画布副本一样，为该图片节点开专属编辑页签

做法：`image:<nodeId>` 进顶层标签（与画布副本同层），激活后内容层挂一个图片编辑工作区，
编辑完关闭页签回到画布；工作区可承载长编辑链（多步处理的历史）。

| 项 | 结论 |
|---|---|
| 空间 | 最好（整屏） |
| 上下文切换 | **仍是一次跳转**：画布 → 页签 → 画布，只是把「弹窗」换成「页签」 |
| 成本 | 高：页签 store 扩展 + 内容层挂载 + 关闭回退 + 按项目恢复 + 每页签独立编辑会话 |
| 与现有模型冲突 | 顶层页签语义是「项目槽位 + 画布副本」；每个图片节点再开页签会让页签条退化成窗口列表，节点一多就爆 |
| 长编辑链 | 页签里的“链”是隐式的，用户看不到节点之间的关系；真要把链变成可复用流程，仍然需要画布 |

### 方向 2：保持按钮，编辑就地发生在节点内

做法：点击裁剪/局部/分割 → 该节点进入**编辑态**（节点临时放大到工作尺寸、工具栏切到
“确认/取消”、图片区渲染裁剪框 / 蒙版笔刷 / 切分网格），确认后照旧产出子节点或改原节点，
退出编辑态恢复原尺寸与工具栏；Esc 取消。

| 项 | 结论 |
|---|---|
| 空间 | 中（节点放大到约 2×，可提供一个「全屏」按钮把同一个编辑器铺满视口，仍不是页签） |
| 上下文切换 | **零跳转**：编辑对象一直在眼前，改完立刻看到结果落回画布 |
| 成本 | 中：把 4 个对话框的“内容体”从 Modal 外壳里拆出来复用 + 节点编辑态 + 画布手势隔离 |
| 与现有模型 | 完全一致：产物本来就是子节点/节点数据，撤销仍走同一命令队列 |
| 长编辑链 | 单节点只负责单步；**多步链交给画布副本**（选中这串节点 → 右键「保存为画布副本」），
  这正好是用户要的“独立流程模板” |

## 三、推荐：方向 2（就地编辑），链路需求交给画布副本

理由（按权重）：

1. **用户痛点是“跳走”，不是“空间不够”**。方向 1 仍然是跳转，只是把模态框换成页签；
   方向 2 才真正消除上下文切换。
2. **图片编辑的产物是图元素**（子节点/节点数据），留在画布上就是最自然的落点；
   弹窗里编辑、画布上出现结果，本来就是两套坐标。
3. **顶层页签的语义不能被稀释**：页签 = 项目槽位（剧本/导演台/画布）+ 画布副本。
   给每张图片开页签，会让“画布”这一层被切成碎片，也违背“1 个项目 = N 块画布”的挂载模型。
4. **长编辑链是图级需求**：链的每一步都是一个图片节点、彼此有连线，这正是画布副本能整体复制成
   模板的场景；给单张图开页签反而把链拆散了。
5. **成本更低、可增量**：先做裁剪 + 分割（已有确定性产物），再做局部遮罩（等后端），
   全程不新增导航层，只新增“节点编辑态”。

落地形态（细节在实现时定）：

- 编辑态 = 节点级 UI 状态（不进 graph 持久化，刷新即退出编辑），节点临时放大并居中；
- 编辑期间节点独占指针事件，画布平移/框选/连线暂停（顶部/底部给一句“按 Esc 退出编辑”）；
- 结果提交：裁剪 → 子节点 + 连线（沿用现有逻辑）；分割 → N 子节点 + 自动成组；局部 → 待后端；
- 撤销：仍通过 `commandQueue` 一次性提交，节点尺寸变化也走同一条命令，Ctrl+Z 可回退；
- 可选增强：编辑态里给一个「全屏」按钮，把同一编辑器铺满视口（不是页签，关闭即回节点），
  用来解决小尺寸下蒙版笔刷精度问题；
- 弹窗保留给「查看大图 / 详情」这类只读场景，不再承载编辑。

## 四、实施拆分（拍板后按此推进）

1. **T1 编辑器内容体拆分**：把 crop / split / mask 三个对话框的 Modal 外壳与内容体分离
   （`CropEditor` / `SplitEditor` / `MaskEditor` 可嵌任意容器），弹窗路径改为薄壳复用同一内容体，
   禁止两套 UI 实现。
2. **T2 节点编辑态**：图片节点新增运行时编辑态（工具入口改为进入编辑态），节点放大/还原、
   内容区承载编辑器、顶部确认/取消、Esc 退出；画布手势隔离。
3. **T3 裁剪 + 分割接线**：确认后沿用现有产物逻辑（子节点、连线、自动成组），撤销走命令队列。
4. **T4 局部遮罩**：内容体就位，后端就绪后接生成（当前保持“未实现”提示，不得假成功）。
5. **T5 全屏扩展（可选）**：同一编辑器铺满视口，Esc 回节点。
6. **T6 验收**：typecheck / 相关单测 / 构建 / 真机实操（裁剪框拖拽、切分网格、手势不串）。

## 五、验收断言（草案）

- 点「裁剪」不弹窗：节点进入编辑态，裁剪框在节点图片上直接拖拽，确认后子节点出现在原节点右侧并连线。
- 点「分割」不弹窗：切分网格覆盖在节点图片上，确认后 N 个子节点成组。
- 编辑态下画布不平移、不框选、不连线；Esc 退出且不改图。
- 撤销：确认后的产物一次 Ctrl+Z 完整回退（含节点尺寸还原）。
- 编辑态节点尺寸变化不写回 graph 持久化（刷新后回到普通态）。

## 六、风险

- 小尺寸节点里做蒙版笔刷精度不足 → 用「全屏」扩展兜底，或编辑态默认按 2× 放大。
- 手势冲突（拖拽裁剪框 vs 拖动画布）→ 编辑态整节点吞掉指针事件，画布层 `pointerEvents:none`。
- 复用对话框内容体时容易分叉出第二套 UI → 内容体只允许一份，弹窗与节点内都 import 它（接线守卫钉住）。
