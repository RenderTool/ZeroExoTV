# C-19 修复：ZeroExoLoraChain 读 LoRA 权重解包崩溃（too many values to unpack）

日期：2026-11-21
报障原文：`生成失败：too many values to unpack (expected 2)？？`

## 根因（日志取证，非猜测）
`D:\ComfyUI\comfyui_run.err.log:102-122`：

```
File "...\custom_nodes\ComfyUI_ZeroExoNodes\lora_chain.py", line 94, in _load_lora_file
    lora, _metadata = comfy.utils.load_torch_file(path, safe_load=True)
ValueError: too many values to unpack (expected 2)
```

本机 ComfyUI 的 `comfy/utils.py:238`：`return (sd, metadata) if return_metadata else sd`
——`return_metadata` 默认 False，所以默认返回的是**权重字典本身**，不是二元组。
`lora, _metadata = {…}` 会对 dict 迭代 key 解包，文件里 key 远多于 2 个 → 报错。

即：调用方按「新版二元组」写，实际拿到「老版 dict」。属于版本兼容问题，不是 LoRA 逻辑问题。

## 修法（版本双向兼容，不赌某一个版本）
1. 新增 `_unwrap_torch_file(loaded)`：dict 原样返回；tuple/list 取第 0 项且必须是 dict；其他形态报明确 RuntimeError。同时容纳 2 元组/3 元组。
2. `_load_lora_file`：先 `load_torch_file(path, safe_load=True, return_metadata=True)`；若该版本没有 `return_metadata` 形参（TypeError）→ 退回 `load_torch_file(path, safe_load=True)`，再走 `_unwrap_torch_file`。
3. `apply_loras`：`load_lora_for_models` 返回值同样按 tuple/list 归一，避免同类解包假设再崩一次。
