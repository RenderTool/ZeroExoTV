# 本集检查：用用户语言，不做工程字段与术语暴露

## 一、用户原话

> review_episode 工具 / WorkbenchShot 增 sceneId / camera / sound / 参考图槽位强类型……
> 你自己根据我们项目实际做！！！你要用用户思维！一个新手他可能压根不懂这些！！！
> 这些是我们的软件的附属价值！！而不是展示一堆用户根本看不懂也看不明白的术语！！！

## 二、结论（不做 vs 做）

**不做**：不把 `sceneId` / `camera` / `sound` 做成用户能看到的字段，不做 `REF-槽位（用途/顺序/控制）`
这种语法展示。新手不需要知道“镜头卡由哪些字段组成”，这些结构留在内部。

**做**：导演台导轨一个「检查」按钮，弹层用大白话告诉用户这一集还差什么，点「定位」跳到第一段有问题的片段：

| 检查项 | 用户看到的话 |
|---|---|
| 画面提示词为空 | 还没写画面提示词 |
| 视频提示词为空 | 还没写视频提示词 |
| 没有参考图 | 还没有参考图 |
| 时长不在 5–15 秒 | 时长不在 5–15 秒 |

- 通过时显示「本集检查通过，可以出片」。
- 弹层只显示当前集（与分集下拉同一可见片段），不扫全项目。
- 只报事实，不改内容；不出现错误码、英文字段名、镜头卡术语。

## 三、实现

- `workbench-episode-check.ts`：纯函数 `buildEpisodeCheck(shots)`，返回段数/总时长/四条 issue + 对应 shotIds。
- 导演台导轨「检查」按钮 + Modal：标题「本集检查」，每条 issue 显示数量与「定位」。
- 测试：`workbench-episode-check.test.ts`（4 类缺口 + 通过态；断言不出现英文字段名）。
