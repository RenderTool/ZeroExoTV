# 不让用户看到半成品：主体空提示词自愈 + 交付前补全

## 一、用户原话

> 我的用户可不像我这样专业，更不可能像我这样知道 MCP 生成的剧本有什么问题，
> 主体没生成提示词、剧本信息没写！只要有一次错误，他们一定会默认我们软件只能处理到这个地步！！
> 很显然这是你的设计问题！！！

## 二、设计原则

**不能靠用户发现缺什么。** 软件必须在「创建 / 打开 / 交付」三个时刻自己把空补上，
或者明确挡住「完成」；只补缺、不覆盖用户已有内容。

## 三、改造

### 主体列表体检（前端）

- 列表顶部新增「项目体检」条：没设全剧风格 → 直接打开画廊；
  有 N 个主体没提示词 → 一键「补上」；有 N 个主体没定妆图 → 提示点开主体去画布生成。
- 卡片封面空态从「暂无封面图」改成「暂无封面图 · 点开可生成」；
- 主体空态文案改成「可以让 Agent 从剧本里提取主体，也可以手动添加」。

### 新建 / 打开主体

- MCP `upsert_subject`：新建主体（或已有空树）时立刻补一条**最小可用提示词**
  （角色单人、场景空景、道具单品 + 全剧风格），返回 `promptSeeded`；`set_subject_profile` 再覆盖成完整模板。
- 前端打开主体：树存在但基础状态提示词为空时，自动用模板补上并落盘；
  用户不应看到「主体卡有、提示词空白」。

### 交付前

- 新增 MCP `ensure_project_ready({ projectId, dryRun? })`：
  - 给没有提示词的主体补最小提示词；
  - 给没写简介的剧本从第一集正文提炼一句（前 80 字）；
  - 返回 `repaired` / `remaining`（还缺几个主体图、几段提示词）与一句**大白话 summary**。
- server instructions：**说「完成 / 可以出片」之前必须调 ensure_project_ready**；
  把 repaired/remaining 用大白话告诉用户，缺图/缺提示词问用户要不要现在补，不提字段名/错误码。
- 老项目仍可先跑 `audit_upgrade` 看历史纰漏。

## 四、边界

- 自动补的是**最小可用提示词**，不是完整三视图字段；完整质量仍走 `set_subject_profile`（有强制字段）。
- 不自动编造主体图、不自动写分镜提示词；这两类在 remaining 里问用户。
- 只补空，不覆盖已有内容；`ensure_project_ready` 默认生效，`dryRun:true` 可先预览。
